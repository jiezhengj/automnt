# Automnt 3.6.1：无证据的挂载丢失不再被当成“你手动弹出”

本次为修复版本（PATCH）。GitHub Release 只提供 CLI 预编译二进制，不含 GUI App。

## 修的是什么

11-24 出现过一个实际故障：网络抖动时 macOS 的 SMB 会话悄悄断开，两个卷从挂载表消失，既没有卸载记录也没有弹出记录。程序把这件事判定为“你在卷健康时手动弹出”，于是这整个会话不再尝试挂回——一整天都没有恢复，只有重启或换网络才会解开。

判定规则里“卷曾健康挂载过、现在不见了”被直接当成弹出证据，这个假设站不住：卷也可能自己丢掉。

## 变化

- **区分“有证据的弹出”和“无证据的丢失”**。只有两种事实算弹出证据：程序自己的弹出动作，或运行期间捕获到的卸载事件（并且当时该卷确实健康、服务器可达）。「曾健康挂载」本身只说明这里本该有卷，不再当证据；缺少证据的丢失按丢失处理，下一轮照常恢复。
- **旧版本留下的抑制会自动解开**。升级前被误判为弹出、且没有证据的抑制记录，在服务器可达时立即放行并重试一次，仍受既有尝试次数与间隔限制，不会变成无限重试。
- **网络恢复后重试一次**。抑制期间如果网络上下文变化（换网络或重新登录），按原规则解除抑制；此外无证据的旧抑制不再需要等边界变化才能恢复。
- **探测超时默认从 1000 毫秒放宽到 3000 毫秒**。走 Tailscale 中继时单程往返常到 300 毫秒以上，TCP 握手需要约两倍往返，原来的 1000 毫秒必然失败。旧配置里写着 1000 的视为“没有自定义过”，读取时静默提升为 3000；手工填过的其他值原样保留。

## CLI 可感知的变化

命令与参数不变。`hosts[].timeout` 未设置或等于旧默认 1000 时，运行时按 3000 毫秒探测；写入的配置文件不会被改写，也不会新增字段。

## 同仓库源码修复（不随本 Release 分发）

- GUI 侧新增卸载事件观察者，把“你确实弹出过”记录下来作为证据；同时修掉“快捷挂载”在全部共享都被抑制时点下去毫无反馈的问题——现在摘要里会列出它们和原因（本次会话中已弹出），不重挂但也不装作没发生。详见 `.specify/bugs/mount-loss-misjudged-as-eject/`。

## 下载

- `automnt`：预编译 CLI（macOS 27 / Apple silicon），下载后先 `chmod +x`。
- `automnt-3.6.1.sha256`：CLI 的 SHA-256 校验值。

## 升级

替换旧 `automnt` 即可，配置与后台状态沿用；旧状态文件里缺新字段的条目按“无证据”读取，正是本次要修的那类。
