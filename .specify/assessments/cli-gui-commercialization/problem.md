# 问题陈述

macOS 用户的文件任务依赖 SMB 卷宗时，重启或网络变化后的未挂载会导致任务先失败，用户再中断工作去 Finder 手动连接。用户需要配置的共享在条件允许时自动就绪、丢失后自动恢复，减少日常工作对人工挂载的依赖；维护者希望将这一能力通过免费 CLI 和买断 GUI 共同提供并持续维护。

# 用户与利益相关者

- **核心用户**：日常文件任务依赖 SMB 共享的人；维护者是直接体验者，扩大人群规模待验证。
- **CLI 社区用户**：需要免费自动挂载能力继续可用，配置与运行行为持续稳定。
- **GUI 购买者**：需要购买并配置后获得持续自动挂载体验；实际购买者与购买量尚未验证。
- **维护者与贡献者**：需要共同能力共同演进，避免两套产品重复维护，并使商业支持承诺可持续。

# 目标

- 减少因配置卷宗未挂载导致的文件任务失败与人工中断。
- 在服务器可达且配置、凭据和权限有效时，保持自动挂载与丢失恢复的核心价值。
- 保留免费 CLI，并让 GUI 承载同一核心价值；共同能力持续一致演进。
- 验证买断商店发行能否兼顾自动化体验和持续维护成本。

# 非目标与当前边界

- 本轮不解决 Finder 侧边栏入口消失，不确认历史 macOS 行为变化的起始版本。
- 不承诺 Windows 式任意网络路径访问时即时连接，也不承诺服务器不可达时仍成功读写。
- 不以状态查看或手动重挂替代正常情况下的自动挂载。
- 不扩展协议、平台、订阅或云账户，不限制社区在 MIT 下的构建与分发权利。
- 本轮不实施产品或发布，不制定技术架构。

# 成功指标

以下指标以核心价值为序；目标数值和样本待确定，不伪造现有数据。

- **任务访问就绪率**：前置条件有效的实际文件任务中，访问时目标卷宗已自动挂载的比例；baseline: 未测量。
- **人工干预率**：重启、网络恢复、卷宗丢失后，需要人工连接才能继续任务的次数；baseline: 维护者报告经常发生，尚无量化。
- **自动恢复延迟与失败原因**：从可达性恢复到卷宗就绪的分布，区分未收到事件、网络未就绪、权限与凭据失败；baseline: 无固定最长延迟保证，数值未测量。
- **无人操作的持续运行**：配置后，约定的登录/网络变化/挂载丢失情景无需打开配置界面或点击重挂；baseline: CLI 有对应机制，本轮未重做真实环境测试，GUI 未验证。
- **共同演进**：两种入口的共同挂载规则与故障修复保持一致，并存时无重复或冲突操作；baseline: 尚只有 CLI。
- **购买与可持续性**：用户对明确自动挂载体验和价格的实际购买选择，以及净收入与支持成本；baseline: 未知。

# 不采取行动的代价

免费 CLI 可以继续提供自动挂载，已有用户不必等待 GUI。没有采用工具的用户仍可能反复遭遇文件任务失败后手动连接的问题。暂缓 GUI 会推迟商店产品的可获得性和收入机会，但规模未知；它不会使核心痛点消失，也不意味着可以用手动挂载界面代替自动化。

# 本轮补充的成功边界

[研究](research.md)已取得收费自动挂载先例和正式后台运行机制；问题成立与类别可发行不再是未知。以下为产品结果约束，不预先指定技术实现：

- 自动挂载后，依赖卷宗的真实文件任务可以通过约定路径读写；仅应用显示“已挂载”不足以验收。
- 首次设置允许必要授权；正常登录、网络恢复和挂载丢失后的自动处理不逐次要求确认或点击。
- 同一用户同时安装两种入口时，共享目标不会被重复挂载，配置意图不会被相互覆盖。
- 用户明确停用自动化时停止运行；关闭配置窗口的行为与退出/停用语义须清楚。
- 竞品存在和公开评论只提供市场信号；首版转化率与支持投入需上市前后持续测量，不能当作已盈利。

# 待澄清问题

1. 核心自动挂载与恢复在目标商店运行及审核边界下能否成立？
2. 商店若不能承载核心价值，是否接受直接签名公证分发或暂停 GUI？
3. 两种入口同时安装时，用户期望怎样的后台控制与配置管理关系？
4. GUI 首版的辅助交互范围、投入上限及买断更新支持承诺是什么？
5. 目标用户规模、买断付费意愿和支持成本是多少？
