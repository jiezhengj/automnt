# 原始发行想法

> 我打算把当前的 CLI 产品持续作为开源、免费的产品发布在 GitHub 作为社区版。
> 但同时，我想在同项目内构建一个 GUI 产品，代码依旧可以开源，但编译后的产品通过 Apple 的 Mac App Store 发布，买断制收费（我不知道收费多少合适）。这样便于那些没有编译能力的用户方便地获取 GUI 产品并使用。
> 而 CLI 和 GUI 应该高度复用、并行演进，而不是各自分支。

# 维护者补充的立项背景

> 本项目最核心、也是一开始立项的痛点就是，macOS 在最近几个大版本（我忘了是哪个版本开始），不能再把服务器主机（而不是其下某个 SMB 卷宗）直接添加到 Finder 的侧边栏，以前是可以的。
> 而就算把主机下某个 SMB 卷宗添加到 Finder 的侧边栏，经常会在重启等情况后，因为系统不会自动挂载 SMB，导致 Finder 侧边栏里的 SMB 卷宗会消失（虽然我们项目目前也还不能解决这个问题）。
> 更严重的问题是，如果有些任务天然需要读写某 SMB 卷宗内的文件，经常是一运行那个任务、报错后才发现，SMB 卷宗没被挂载，于是要去手动挂载一下。
> 所以这个项目的核心能力就是自动挂载。
> 如果是要手动重新挂载，用 Finder 就够了啊。

维护者同时以 Windows 通过网络路径访问文件、不需先人工挂载的体验作比较。这是目标体验的来源，不作为所有 Windows/macOS 环境的一般化技术结论。

# 中性转述

探索把现有 SMB 自动挂载产品扩展为同项目内共同演进的两个入口：免费的开源 CLI，以及可开源、通过 Mac App Store 买断销售的 GUI。GUI 必须承载自动挂载这一核心能力，使用户在配置完成后的正常使用中减少因卷宗未挂载导致的任务中断；图形交互是该能力的配置与管理入口。

# 来源与背景

- **提出者**：项目维护者，也是立项痛点的直接体验者。
- **背景**：重启或网络变化后缺少自动挂载，文件任务可能在用户知情前失败。当前产品已经提供自动挂载与恢复；当前平台范围为 macOS 27+ Apple silicon。
- **已知边界**：尚未解决 Finder 侧边栏入口消失，也没有任意网络路径访问时即时连接的机制。
- **发行意向**：免费 CLI 持续发布；同项目 GUI 买断商店发行；高度复用与并行演进，不长期分叉。
- **评估边界**：此次不实施产品、不修改业务代码、不发布；维护者另行明确授权把立项背景写入长期项目文档。
