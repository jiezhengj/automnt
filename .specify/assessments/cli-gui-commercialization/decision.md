# 判决与理由

**go：推荐概念 A，进入同项目自动挂载 GUI 的规格定义，优先 Mac App Store 买断发行。**

公开证据不再支持因“商店可能不允许自动挂载”而无限暂缓：已有收费自动挂载产品在当前系统持续维护，Apple 也明确支持用户授权的后台服务和商店应用内嵌 CLI。没有发现足以直接 kill 这一方向的法律、平台类别或产品价值障碍。MIT 收费兼容，免费 CLI 与 GUI 共同演进有正式代码复用路径。

但不推荐把现有 CLI 原样打包，也不以竞品 Helper 的存在保证审核。此次 go 的标准是值得定义和验证产品，而非已经证明整个项目会成功。实际沙盒挂载与盈利仍未验证；正式能力验证是后续实施前必须明确安排的高风险工作，不能在 Assessment 中假称通过。

# 可终止商店路线的条件

这些是后续验证的停止条件，当前没有宣称已经发生：

1. 必须挂载到任务无法使用的位置，或无法维持约定路径。
2. 登录、网络恢复或卷宗丢失后必须逐次确认或手动点击，核心自动化不成立。
3. 凭据或权限不能持久安全授权，配置后的正常运行仍反复中断。
4. 无法合规交付必要的后台/挂载帮助程序，必须靠外装不受限 CLI 或 root 提权规避规则。
5. 死卷恢复或两入口共存无法在可接受预算内保持原有核心语义。
6. 可靠性与支持成本验证显示产品成本明显高于可接受投入，且没有可信的差异价值或购买信号。

触发时停止 A；由维护者另行选择 B（直接签名公证发行）或 C（暂缓 GUI）。这不否定 CLI 自动挂载产品，也不能授权换渠道后自动开发。

# 交接给 `$speckit-specify`

- **Problem**：依赖 SMB 文件的任务因共享未挂载而失败；需要配置后自动就绪与恢复，减少人工补救。
- **Chosen approach**：A，免费 CLI 持续发布，同项目买断 GUI 提供完整自动挂载核心；共同规则和修复共同演进，发行适配允许不同。
- **In scope**：现有 SMB 平台范围；首次配置和授权；后台自动挂载与恢复；任务可使用的挂载路径；健康弹出/停用意图；必要诊断；双入口共存；商店注册与更新方式。
- **Out of scope**：手动挂载作为正常主流程、多协议扩张、Windows 式任意路径即时连接、Finder 侧边栏修复承诺、云账户、订阅、长期业务分叉；不擅自扩展系统范围。
- **Success metrics**：实际任务访问就绪率、人工干预率、恢复延迟及失败分类；真实文件读写而非界面挂载标记；登录和网络变化无需逐次操作；无重复挂载与配置覆盖；购买转化与支持工时。目标阈值在规格中确定。
- **Carried-forward open questions**：沙盒 NetFS 与指定路径、凭据持续授权、死卷清理、后台事件、必要 helper 合规、退出语义、配置兼容与共存方式、有限投入预算、买断更新支持承诺。具体实现选择属于 plan。
- **价格建议**：US$9.99 / 中国区 ¥68 附近可用价格点作为首版测试建议；非正式售价授权，不承诺两个价格等价或最优。依据和成本情景见 research / concept。
- **Appetite 建议**：先对核心可行性验证设 medium（weeks）、最多两周的预算候选，后续由维护者确认；不伪装为工期估计或实施授权。
