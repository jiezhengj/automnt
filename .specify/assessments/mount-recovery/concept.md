# Concept: 挂载丢失后的傻瓜化恢复（修订版 v2）

- **Slug**: mount-recovery
- **Created**: 2026-10-04（v2：按维护者方向修订——调研前置至裁决前、C 为 B 的指定备选、C 形态再调研）
- **Recommended option**: Option B（事件化智能恢复 + 自有动作台账），备选 Option C（升级形态）

## 选项（含补充调研后的机制证据）

### Option B — 事件化智能恢复（丢失检测 + 自有动作台账 + 有界自动重挂）
- **Sketch**: 在现行事件驱动框架内为“产品配置并挂载的卷”建立**自有动作台账**：仅当挂载是被产品自身因失效而清理、或在无用户卸载动作的情况下消失时，登记“待恢复”；主机可达后有界重挂并销账；用户手动卸载永远不入账、永不自动重挂（对齐 Ejectify 的“只恢复自己动过的卷”范式，其产品甚至把“eject=禁用自动重挂”直接做成开关语义）。恢复行为可配开关，失败转通知引导。
- **Appetite**: medium
- **Trade-offs**: 赢——绕开“事件层无成因字段”的判别死结（DiskArbitration 头文件实锤），用自有动作台账满足“误覆盖=0”硬指标；同时覆盖“丢挂载后零触发器”缺口。输/风险——台账的跨上下文粘性语义（用户卸载后网络抖动是否解禁）是设计关键；系统自行强制卸载的“干净缺失”漏记属安全方向失败（不恢复但不越权）；实机校准（stale vs 干净缺失的出现比例）需在规格化阶段取证。
- **Rabbit holes**: 台账持久状态与配置数据模型零变更约束的调和；唤醒/睡眠与网络切换的竞态；凭据失效型“恢复也挂不上”的分支处理。

### Option C — 受限周期重评估（指定备选，升级形态）
- **Sketch**: 保留“周期检查缺失即恢复”的骨架，但按调研升级三处：①触发优先用官方 `StartOnMount`/现有网络事件，周期仅作兜底（且知悉 `StartInterval` 睡眠漏触发的文档缺陷）；②上下文门控（网络身份变化才允许恢复，参照 Mounty 的 SSID 门控实践）；③同样携带自有动作台账与幂等检查（已挂载不重复挂）。
- **Appetite**: small ~ medium
- **Trade-offs**: 赢——机制直观、覆盖无事件场景最彻底；输——“周期”部分与 3.0.0 对外“杜绝轮询”承诺及宪法 II“按需启动”的解释压力仍在；节奏参数需实证校准；即便有台账，周期性唤醒本身的成本与抖动风险高于纯事件形态。
- **Rabbit holes**: 宪法 II 兼容性辩论；节奏/耗电争论；与用户卸载动作的竞态窗口。

### Option A — 可发现性修复（通知引导 + 一键重挂）
- **Sketch**: 不自动挂载；评估时发现配置卷缺失即通知“点击恢复”，`--config` 菜单提供“立即重新挂载”，文档补一节。
- **Appetite**: small
- **Trade-offs**: 零意图冲突、零宪法张力；但“零触发器”场景连通知都不会来，硬指标 2（无需重启恢复）不达标。按维护者方向，A **不再是 B 的备选**，仅保留为最小对照项/可与 B 叠加的引导层。
- **Rabbit holes**: 通知交互平台细节。

### Option D — 不作为 / 依赖第三方
- **Sketch**: 维持现状或文档推荐第三方工具。零投入但承诺持续受损；与产品定位相悖。案例调研确认第三方（Ejectify/Mounty）各有可借鉴范式，但没有直接可替代的现成品。

## Recommendation

**Option B（主），Option C（备）**，均建立在补充调研已完成的基础上：

- 调研已回答两个前置问题：**(1) 意图判别**——事件层无成因信号（DA 头文件），但“自有动作台账”范式经 Ejectify 实证可在不判别成因的前提下保证误覆盖=0；**(2) C 的更优形态**——官方 `StartOnMount` 挂载事件、`WatchPaths` 官方警示（现行依赖有漏事件风险）、`StartInterval` 睡眠漏触发缺陷、Mounty 的网络上下文门控与幂等实践，均已被吸收进 C 的升级形态。
- 若 B 在实现期被台账语义/宪法兼容性证伪，则回退 **C（升级形态）**——它以周期兜底换取最彻底的覆盖，代价是原则张力，需要你届时裁决对外承诺口径。
- A 不再作为回退候选（无法满足硬指标 2），但其“通知+一键”元素可作为 B/C 的失败兜底层叠加。

## Out of Scope (for the recommended option)

- 服务端/链路不稳定治理；离线期间维持挂载；恢复过程中的凭据交互。
- 配置数据模型大改（台账持久状态若需要，最小形态须显式过宪法/数据模型零变更审查）。
- 第三方工具集成；跨用户/多配置场景。

## Assumptions to Validate

- A1'（已收敛）：意图语义由自有动作台账承载，不依赖成因判别——文档级已成立；**实机校准项**（断网丢失的实际形态：stale 滞留 vs 干净缺失的比例）转入规格化阶段验收取证，只影响覆盖面、不影响方案成立性（漏记=安全方向失败）。
- A2：宪法 II 下台账+事件触发的实现形态不构成常驻等待进程/独立运行循环（plan 阶段合规审查）。
- A3：症状个案根因是挂载缺失/死卷（非凭据失效）——个案取证并行。
- A4：台账粘性语义（用户卸载后跨网络抖动不自动解禁，需显式恢复）符合用户预期——shape/specify 中与你确认。
- A5：问题规模数据待补（影响投入档位，不阻塞）。

## 修正（2026-10-05，维护者质询后）——B' 分层语义与诚实覆盖面

台账层的意图保护（误覆盖=0）成立，但覆盖面经质询修正为分层模型：

| 层 | 行为 | 覆盖场景 | 残余死角 |
|---|---|---|---|
| L3 stale 清理+记账恢复 | automnt 清死卷时记账，可达后恢复 | 断网→stale→清理→网络回归 | 无账不恢复（安全方向） |
| L1 可达性迁移恢复 | 不可达→可达迁移时恢复全部缺失配置卷 | 弹掉死卷后网络回归；系统清理后网络回归；断网丢失 | 主机一直可达时弹掉死卷 |
| L2 会话内抑制 | 卸载时主机可达=健康弹出→本会话抑制 | 3.0.0 抱怨场景（健康弹出不被打扰） | 死卷弹出在主机已回归时被误判为健康弹出 |
| L4 通知/一键重挂 | 缺失且被抑制时可见引导 | 全部残余死角的兜底 | 需用户点一下（非全自动） |

**B' = L1+L2+L3+L4**：主症状（网络丢失恢复）由 L1 保障——不再依赖“知道谁卸载”；3.0.0 抱怨由 L2 保障（启发式，误判方向是“少恢复”而非“覆盖意图”）；残余死角由 L4 可见兜底。

**语义待维护者拍板（决定 L2 的体验边界）**：健康弹出的抑制是**会话级**（网络/登录迁移后自动解禁，可能在用户“就想让它消失”时于下次网络抖动后重挂回来）还是**永久**（直到用户显式恢复；死卷修复场景的死角变大，靠 L4 兜底）。

## 判别层定稿（2026-10-05 实测取证后）——三重信号

| 信号 | 判定 | 依据 |
|---|---|---|
| 挂载缺失 + 非 automnt 自账 | 用户弹出 → 抑制 | 丢失不产生卸载（72h 实测），缺失=曾被卸载；排除法归因 |
| 挂载在表但失效/重连中 | 网络丢失 → 恢复（stale 清理+重挂） | smbfs 原地重连（实测），产品已有清理能力 |
| 缺失 + 卸载前存在会话丢失证据（smb_iod_start_reconnect） | 修复弹出（弹掉死卷）→ 允许恢复 | 内核日志时间线（丢失侧样本已捕获） |

失败方向安全：任一信号缺失/日志不可读 → 保守抑制 + L4 通知/一键兜底。对照实验（真实弹出+真实断网各一组）为验收校准项。

## 概念澄清（2026-10-05，维护者两轮追问后定稿措辞）

### automnt 的能力边界（明确承诺）

- **automnt 没有、也不会有弹出/卸载功能。** “台账”仅指两本既有/自然存在的记录：
  1. **挂载账**：automnt 挂载过哪些卷；
  2. **清理账**：automnt 清理过哪些**死卷**（即既有“断网失效挂载的超时强制清理”能力的执行记录）。
- automnt 从不主动卸载健康卷。判定规则一句话：**卷缺失，只要不是 automnt 清理死卷造成的，即视为“用户弹出”——本会话内绝不自动重挂。** 无需、也不存在“弹出台账”；归因靠排除法。

### B' 的触发模型（与 C 的本质区别）

- **B' = 纯事件唤醒，不轮询**：登录（RunAtLoad）＋网络配置变化（现有 WatchPaths，官方标注竞态漏事件，待评估加强）＋挂载命名空间变化（`StartOnMount` 官方键与 /Volumes 增删——用户弹出、卷回归都会唤醒）。每次唤醒做一次短命判定（看挂载表＋两本账 → 挂/不挂/记账），跑完即退，无常驻进程，保全 3.0.0“杜绝轮询”承诺与宪法 II。
- **C = 周期兜底闹钟**（事件仅作加速）：覆盖“什么事件都没来”的死角最彻底，代价是与“杜绝轮询”承诺有张力、节奏参数需实证。
- 失败方向一致安全：漏醒/漏事件 = 少恢复几次 + L4 通知/一键兜底；判定无证据 = 保守抑制。
