# Problem Definition: 挂载丢失后的傻瓜化恢复

- **Slug**: mount-recovery
- **Created**: 2026-10-04
- **Inputs used**: intake.md | research.md | user input

## Problem Statement

当 SMB 挂载因远程主机或网络不稳定而丢失后，产品没有任何傻瓜化的恢复途径：守护服务只在登录与网络配置变化时重新评估，挂载丢失本身不触发任何动作；非技术用户不知道裸 `automnt` 命令可以重新挂载，只能重启电脑恢复。这与产品“静默、免密码、傻瓜化”的核心承诺相悖。

## Affected Users & Stakeholders

- **Users**: 远程主机（如 Tailscale 异地互联）环境下的 automnt 使用者，尤其非技术用户 — 挂载丢失后无法自行恢复，被迫重启电脑 [source: 维护者口述、research.md]
- **Users**: 会主动手动卸载 SMB 卷的使用者 — 任何“缺了就挂”的恢复机制若无意图判定，会覆盖其手动卸载意图（3.0.0 之前已实际发生）[source: 维护者口述、git edf17d5]
- **Stakeholders**: 项目维护者 — 拥有产品“傻瓜化”承诺、支持成本与宪法 II/事件驱动设计原则的守护责任与最终决策权

## Goals

- 挂载因**非用户意图**的原因丢失后，存在傻瓜化恢复路径（自动或一键式），无需重启电脑、无需命令行知识。
- 恢复行为绝不覆盖使用者手动卸载的意图。
- 恢复机制与宪法 II（按需启动、无常驻等待进程）及现行事件驱动设计原则兼容，或给出有说服力的兼容论证。
- 远程不稳定主机场景下的抖动（挂载↔掉载循环）可控、可感知。

## Non-Goals

- 不解决服务端或网络链路本身的不稳定性——只负责本机侧的挂载可用性。
- 不保证主机离线期间维持挂载；离线期间不挂载，主机回归后恢复可用即可。
- 不引入任何需要用户输入凭据或弹窗交互的恢复过程。
- 不在本问题定义阶段预定任何具体机制（轮询、事件、通知等均为后续 shape 阶段的方案空间）。

## Success Metrics

- 丢挂载事件发生后，无需重启电脑即可恢复挂载可用状态（baseline: 今天仅重启或懂命令的用户手动 `automnt` 可恢复）。
- 用户手动卸载被自动重新挂载的误覆盖次数必须为 **0**（baseline: 3.0.0 之前存在；3.0.0 后因无自动重挂而为 0，任何新机制不得使其大于 0）。
- 非技术用户无需查阅文档即可完成恢复（定性指标，验收以现场可用性为准）。
- 宪法 II 合规审查通过（无新增常驻等待进程、无独立运行循环）。

## Cost of Inaction

每次远程主机不稳定都可能造成一个“直到重启才恢复”的死挂载；受影响用户直接感知为产品失灵，与“傻瓜化”承诺相反；问题会随远程用户群增长而放大，并转化为支持请求。受影响规模目前未量化 [NEEDS CLARIFICATION]。
