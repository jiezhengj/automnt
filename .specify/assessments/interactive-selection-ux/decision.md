# 决策结论与裁决依据 (Verdict & Rationale)

裁定结果：**【go】**

Feature 002 虽然成功落地了主机顺位排他探测与标准挂载点推导的核心业务逻辑，但将 2.7.4 沉淀的优质光标单选与复选框交互降级为命令行手动输入代号，产生了明显的用户体验倒退。经对问题空间、历史经验、技术边界与概念方案的深入评估，Option A（原生 TUI 交互范式全面重构）具有极高的问题真实性、极佳的实现可行性与极低的架构副作用。正式批准推进至 Feature SDD 阶段（`$speckit-specify`）。

# 移交规格阶段基准 (Handoff to speckit-specify)

- **核心问题 (Problem)**：全面治理初始化向导（`--init`）与日常管理（`--config`）中让使用者手工键入选项代号的粗糙交互，恢复并超越 2.7.4 的高阶 TUI 体验。
- **选定方案 (Chosen approach)**：Option A — 原生 TUI 交互范式全面重构（深度融合 2.7.4 原生机制与 3.1.0 架构）。
- **五大落地交互范式**：
  1. **单选即直接确定**：动态候选主机、主菜单动作、主机下属操作项采用光标上下键高亮 + Enter 立即选定进入；
  2. **空格单选再回车确认**：高风险破坏性操作（清空/删除主机）与更新信道切换采用 Space 切换 `(o)` + Enter 确认；
  3. **空格多选再回车确认**：从属共享勾选、批量删除与批量状态切换采用 Space 切换 `[x]` + `a` 全选 + Enter 批量提交；
  4. **全局 Esc 即时安全回退**：任何选单、复选框与文本输入行按下 Esc 立即整行擦除并安全回退上一级，不产生脏数据；
  5. **必要受限文本输入**：仅在未挂载主机地址、主机友好别名及未挂载共享 URL 等必要场景保留单行输入。
- **边界与非目标 (Scope Boundaries)**：
  - In scope：选单重构、按键捕获、原地 ANSI 重绘、非 TTY 管道流式降级、按键队列内存模拟自测试套件。
  - Out of scope：不引入 ncurses 或任何外部 Swift Package；不改动 `HostConfig` / `SMBShareConfig` 底层数据结构；不改动运行时顺位排他探测与挂载核心。
- **关键成功指标 (Success Metrics)**：
  - 选单代号手动输入发生率彻底归零（0%）；
  - 标准配置流转的按键效率以同任务、同状态实测记录并报告（不设预设百分比目标）；
  - 全局 Esc 安全回退率达到 100%；
  - 自动化自测套件全绿通过率 100%。
- **移交遗留问题 (Open Questions)**：
  - 列表超长（>20 个卷宗）时的终端窗口高度安全截断与分页滚动策略。
  - 顺位调整采用“两步单选（源主机 ➔ 目标位置）”以保证操作原子性与直观性。
