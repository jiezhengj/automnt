# 问题陈述 (Problem Statement)

使用者在运行初始化配置向导（`--init`）与日常管理菜单（`--config`）时，被迫在屏幕提示与键盘输入行之间来回比对并手动敲入数字与字母代号（如 `[1-2 / m / s / d]`、`[1-1 / a / m / d / u / q]`），无法通过方向键、空格和回车直接进行直观的单选与多选交互。这种交互模式不仅操作繁琐、极易引发误键入，且与历史版本（2.7.4）的高阶终端体验相比发生了严重退化，违背了现代专业 CLI 工具的操作直觉。

# 受影响使用者与利益相关者 (Affected Users & Stakeholders)

- **使用者 (Users)**：macOS 终端使用者与 NAS 维护者 —— 在初始化配置、挂载点勾选、从属共享维护、主机顺位调整及更新策略设置时，频繁面临需要对照多项代号并手动敲字确认的高心智负担与输入摩擦。
- **利益相关者 (Stakeholders)**：项目维护者 —— 关注产品的交互品质感、品牌专业度以及长期的操作鲁棒性，明确要求全面恢复并超越 2.7.4 的交互水准，杜绝低质的命令行代号交互。

# 核心目标 (Goals)

- **淘汰选项代号手工键入**：全面移除向导与日常管理中所有要求使用者手动敲入选项数字或字母缩写（如 `1-2`、`a/m/d/u/q`）的提示行。
- **标准交互范式全量覆盖**：将全系统的所有终端交互严格分层并落地为五大标准范式：
  1. 单选即直接确定（光标上下移动高亮 + Enter 直接触发）；
  2. 空格单选再回车确认（用于高风险破坏性操作的二次防呆确认）；
  3. 空格多选再回车确认（用于名下从属共享的多选批量勾选/删除/切换）；
  4. 全局 Esc 即时安全取消回退（任何环节按 Esc 立即擦除行并返回上一级）；
  5. 仅在录入未挂载主机、别名及共享 URL 时保留单行文本输入。
- **零外部依赖底座坚守**：保持纯原生单文件 Swift 架构，严格依托 Darwin POSIX termios 与标准 ANSI 转义码，绝不引入重型第三方 TUI 依赖。
- **环境自适应降级保障**：在 CI 自动化流水线、重定向管道与自测模拟环境（非 TTY）下，保持 100% 确定性的标准输入流优雅降级与可测试性。

# 非目标 (Non-Goals)

- **不引入重型全屏 TUI 框架**：不引入 ncurses、curses 动态库或外部 Swift 包管理器依赖，坚守单文件纯原生架构。
- **不改动底层配置实体数据模型**：`HostConfig`、`SMBShareConfig` 与 `AutomntConfig` 的字段定义及 plist 存储格式保持稳定，不发生 schema 变更。
- **不改动核心运行时挂载与探活逻辑**：顺位排他探测、NetFS 静默挂载、钥匙串托管及 LaunchAgent 事件驱动架构保持完全不变。

# 成功指标 (Success Metrics)

- **选单代号手工键入率**：在常规选单与配置流转环节，要求输入选项代号的提示行数量降为 **0 个**（基准：当前向导与管理菜单均为 100% 编码键入）。
- **选单操作按键步数与摩擦**：以“光标直接移动回车”取代“阅读提示 ➔ 输入字符 ➔ 回车确认”的代号式操作；按键效率以同任务、同状态实测衡量（原文所写“减少 50% 以上”系无实测依据的乐观估计，维护者已于 2026-10-04 裁决移除）。
- **取消操作一致性**：在所有选单、复选框与输入行中，按下 Esc 键的即时擦除并安全回退成功率达到 **100%**。
- **自动化测试回归率**：在模拟按键流驱动下，内置全量自测试套件保持 **100% PASS**（退出码 0）。

# 不作为的代价 (Cost of Inaction)

若不对该退化进行彻底治理，使用者在每次使用 `automnt` 进行主机增删、共享管理与顺位配置时，都将持续承受原始粗糙的打字交互摩擦；不仅操作易错率居高不下，且与历史 2.7.4 版本相比形成强烈的负向落差，直接削弱产品的核心竞争力与专业口碑。
