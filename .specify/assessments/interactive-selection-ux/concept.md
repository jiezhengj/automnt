# 备选概念方案 (Options)

### Option A — 原生 TUI 交互范式全面重构（深度融合 2.7.4 原生机制与 3.1.0 架构）

- **方案概述 (Sketch)**：
  在保持纯原生 Swift 单文件与零外部依赖的前提下，深度复用并演进 2.7.4 验证成熟的 Darwin termios + ANSI 原地重绘引擎。全面替换 `--init` 与 `--config` 中的所有手工敲字符代号提示行，将全系统交互严格收敛为五大标准范式：
  1. 动态候选主机列表、日常管理主菜单、主机下属操作项全面接入基于光标移动高亮的单选组件（上下箭头/jk 移动，Enter 直接确定并触发）；
  2. 破坏性操作（如清空或删除主机）与自动更新策略切换采用显式单选（Space 切换 `(o)`，Enter 提交确认）；
  3. 主机名下从属共享勾选、批量删除与批量状态切换采用多选复选框（Space 切换 `[x]`，`a` 键全选/全不选，Enter 批量确认）；
  4. 全局任何选单与文本行按下 Esc 键立即整行擦除并安全回退上级菜单，不留存脏数据；
  5. 仅在未挂载新主机、别名及共享 URL 等必要场景保留单行文本输入。
- **项目预算 (Appetite)**：small（约 2~3 天实施周期）
- **权衡分析 (Trade-offs)**：
  - *收益*：100% 消除使用者手动对照代号打字的摩擦感，全面恢复并超越 2.7.4 的流畅操作体验；彻底理清交互边界，大幅降低误操作率；
  - *代价*：需要重新梳理向导与日常管理的菜单状态机；需要对混合选单（数据条目 + 动作项）进行平滑的数据结构适配；
- **潜在陷阱 (Rabbit Holes)**：
  - 当候选主机或从属共享数量较多时，原地上移行数较多，需防范终端窗口尺寸不足导致的滚屏；
  - 必须确保在自动化自测中具备可靠的按键流注入机制（如 `mockKeyInputs`），避免在无人工终端下发生死锁或阻塞。

### Option B — 单键快捷键即时直达模式（Single-Key Direct Dispatching）

- **方案概述 (Sketch)**：
  不采用上下光标移动和原地屏幕重绘机制，而是为每个选项绑定唯一的单键监听（例如在主菜单中按数字 `1` 直接进入主机 1，按 `a` 键立即新增，按 `q` 立即退出，无需回车）。
- **Appetite**：small（约 1~2 天实施周期）
- **Trade-offs**：
  - *收益*：虽然省去了敲回车键的步骤，代码实现相对简短；
  - *代价*：使用者视线仍然需要在屏幕打印的字母/数字代号与键盘按键之间来回搜寻；当主机数量较多或选项复杂时，单键容易耗尽并产生键位冲突；多选场景无法通过单键直达完成；极易因误触单键即时触发破坏性操作（如误按 d 立即删除）；未能从根本上解决使用者提出的“单选/多选/空格/回车”分层体验诉求。
- **Rabbit Holes**：
  - 键位耗尽与符号歧义；无法提供直观的可视化高亮焦点。

### Option C — 维持现状（Do Nothing）

- **方案概述 (Sketch)**：
  保持当前 3.1.0 的文本提示行模式，使用者继续手动输入复合代号（如 `[1-2 / m / s / d]`、`[1-1 / a / m / d / u / q]`）并敲回车。
- **Appetite**：zero（零成本）
- **Trade-offs**：
  - 零研发投入，但交互体验持续退化，严重背离项目易用性目标，持续引发使用者的负向体验与抱怨。

# 方案推荐与决策建议 (Recommendation)

强烈推荐采用 **Option A（原生 TUI 交互范式全面重构）**。

**推荐理由**：
1. **完全契合核心诉求**：Option A 精准落实了使用者明确指示的“单选直接确定、空格单选再回车、空格多选再回车、全局 Esc 返回、受限保留手动输入”五大边界，彻底终结了“看代号敲字符”的倒退现象。
2. **历史经验支撑**：2.7.4 已经充分证明了该方案在纯原生 Swift + Darwin POSIX termios 体系下的高度可行性与卓越体验。
3. **架构正交性**：本次重构仅涉及终端表现层与交互状态机，底层的数据模型（`HostConfig`、`SMBShareConfig`）、配置落盘及运行时挂载探活完全保持不变，架构风险极低且收益极大。

# 推荐方案的排除边界 (Out of Scope)

- **绝不引入第三方外部 UI 库**：不引入 ncurses、curses 动态链接库或任何外部 Swift Package，坚守纯原生零依赖底座。
- **绝不改动已稳定的配置存储模型**：`automnt.plist` 的 XML 结构及版本规范保持完全向下兼容，无需进行配置断代重构。
- **绝不更改运行时核心功能**：顺位排他探测短路、后台静默休眠、Spotlight 防索引及钥匙串托管保持原样。

# 待验证的核心假设 (Assumptions to Validate)

- **假设 1**：当前主流终端仿真器（macOS Terminal.app、iTerm2、Ghostty、Alacritty）均标准支持 `\u{1B}[NA`、`\u{1B}[J` 与 `\u{1B}[K` ANSI 重绘转义码，重绘过程平滑无闪烁。
- **假设 2**：在非 TTY 环境（`isatty(STDIN_FILENO) == 0`，如 CI 流水线或管道重定向）下，单选与多选组件均可通过标准行输入（输入序号、逗号分隔多选或 q 取消）平滑降级，确保 100% 兼容。
- **假设 3**：内置自动化测试套件可通过纯内存按键队列模拟全部单选、多选与 Esc 交互，测试执行无阻塞且毫秒级完成。
