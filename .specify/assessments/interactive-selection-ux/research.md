# 需求与使用者痛点证据 (Users & Demand)

- **使用者真实操作摩擦**：在真实终端运行 3.1.0 时，向导要求在 `请选择操作 [1-2 / m / s / d]` 中手工键入代号，日常管理要求在 `请选择操作 [1-1 / a / m / d / u / q]` 中手工键入代号，操作者不仅需要视线在选项说明与底部输入提示之间来回比对编码，且极易输错（如误输空格、大小写混淆、符号漏打）。[来源：项目维护者真实使用反馈，置信度：high]
- **交互严重退化的落差感**：使用者明确指出，在 2.7.4 版本中所有选单均已具备平滑的单选与多选组件；到了 3.0.0 与 3.1.0 版本，虽然修复了主机顺位与挂载点等核心逻辑，但交互界面却发生了灾难性的倒退，重新跌入“手工敲编码”的原始命令行泥潭。[来源：项目维护者真实对比反馈，置信度：high]
- **清晰分层的交互诉求**：使用者要求彻底梳理全部交互点，并明确划分“单选即直接确定”、“空格单选再回车”、“空格多选再回车”、“全局 Esc 即时返回”与“必要保留的手动文本输入”五大交互边界，使终端体验达到现代专业 CLI 水准。[来源：项目维护者明确指导，置信度：high]

# 历史经验与同类方案 (Prior Art)

### 1. 项目内部实现对比 (2.7.4 vs 3.1.0)

- **2.7.4 原生实现 (`auto_mount.swift:1587-1800`)**：
  - 拥有完整的 `TerminalUI.readKey()`，支持精确识别上下方向键（`↑`/`↓`）、`j`/`k`、回车（`Enter`）、空格（`Space`）、全选（`a`）与取消（`Esc` / `Ctrl+C`）；
  - `promptInteractiveRadio`：渲染 `❯ (●) Title (subtitle)`，上下移动光标，Enter 即刻选定，Esc 即刻取消返回 `nil`；非 TTY 环境自动降级为序号输入；
  - `promptInteractiveCheckbox`：渲染 `❯ [●] Title (subtitle)`，空格翻转单项，`a` 键全选，Enter 批量确认，Esc 取消；
  - 核心菜单均基于以上两个组件驱动，整体体验平滑流畅。
- **3.0.0 与 3.1.0 的退化原因**：
  - 在重构配置架构（消除 profiles 引入 hosts）过程中，开发者为图省事，在 `runInitWizard` 与 `manageConfiguration` 中普遍直接调用了 `promptLineWithEsc`，打印死板的文本列表并要求用户键入字符串，导致 2.7.4 沉淀的优质 TUI 组件被边缘化或废弃。

### 2. 行业主流 CLI / TUI 标杆实践

- **GitHub CLI (`gh`)**：
  - 仓库/PR 切换与操作选单：纯光标上下移动，Enter 直接确认执行；
  - 标签/审查者选择：Checkbox 模式，空格切换勾选 `[x]`，Enter 批量提交；
  - 任何环节按下 Esc 立即安全取消退出。
- **Charm Bracelet (`gum` / `huh`)**：
  - 确立了现代 Go/Shell TUI 的黄金交互规范：单选使用 `choose`（移动+回车），多选使用 `checkbox`（空格打勾+回车），文本使用 `input`（带默认值回车继承）。
- **前端脚手架 (`create-vite` / `npm init` / `inquirer.js`)**：
  - 模板选择直接上下键选定，插件特性使用空格多选，项目名称保留单行输入。

# 现实背景与不作为成本 (Market & Context)

- **产品定位契合度**：`automnt` 定位为轻量、专业、优雅的 macOS 原生 SMB 挂载利器。对于非开发者的终端使用者而言，终端交互的第一印象决定了工具的品质感与可信度。让使用者对照控制台敲入复杂的复合代号（如 `1-1 / a / m / d / u / q`）具有强烈的粗糙感与极高的心智负担。
- **不作为的代价 (Cost of Doing Nothing)**：
  - 使用者在配置主机与日常维护时持续产生沮丧感；
  - 输入代号极易发生无效输入与边界重试，降低配置效率；
  - 与 2.7.4 相比形成鲜明的负向体验倒退。

# 平台边界与技术约束 (Data & Constraints)

- **目标平台约束**：macOS 27.0+（Apple silicon arm64 架构），Darwin 内核环境。
- **零外部依赖原则**：绝对禁止引入重型 ncurses 动态库或第三方外部 Swift 包，必须基于纯原生 Swift 标准库 + Darwin POSIX 接口（`termios`, `read`, `poll`）及 ANSI 转义序列实现。
- **ANSI 屏幕渲染控制规范**：
  - 光标复位与清屏序列：`\u{1B}[NA`（光标上移 N 行）配合 `\u{1B}[J`（清除光标后所有行）与 `\u{1B}[K`（清除当前行），保证原地重绘无闪烁、无残留；
  - 隐藏与恢复光标：在交互选单运行期间通过 `\u{1B}[?25l` 隐藏光标，退出时通过 `\u{1B}[?25h` 恢复光标（必须由 `defer` 保证）。
- **非 TTY 管道与自动化测试约束**：
  - 在 CI 环境、自动化测试或重定向管道（`isatty(STDIN_FILENO) == 0`）下，必须保留无交互的标准输入流降级模式，绝不可在非 TTY 管道下强制启用 `tcsetattr` 原始模式；
  - 内部自测试套件（`--self-test`）必须能够通过模拟按键注入队列（如 `mockKeyInputs`）对交互选单进行 100% 确定性的无人工自动化验证。

# 潜在风险与负向证据 (Evidence Against the Idea)

- **风险 1：长列表滚屏与超出终端高度**：
  - 若候选主机或从属共享数量超过当前终端窗口可见行数，简单的 ANSI `\u{1B}[NA` 上移重绘可能会导致终端滚屏错位。
  - *应对证据*：一般家庭或企业 NAS 挂载点在 1~10 个之间，通常在 24 行终端高度之内；但在设计中可加入可见项截断或通过 `ioctl(STDOUT_FILENO, TIOCGWINSZ, ...)` 动态感知终端尺寸做保护。
- **风险 2：混合选单的焦点逻辑（动态主机 + 操作项）**：
  - 在向导候选列表中，既有扫描出的主机，又有“手动添加”、“跳过”、“完成”等动作项。若混在同一个单选列表里，光标定位与选择派发需清晰解耦。
  - *应对证据*：2.7.4 中已成功验证过将动作项以 `SelectionOption` 统一封装并按索引分支处理的模式，结构清晰且易于维护。
