# 用户场景与验收测试

## 用户故事 1 - 首次向导的主机与共享高阶 TUI 选单重构 (Priority: P1)

使用者在运行 `automnt --init` 初始化向导时，系统不再呈现文本代号提示并要求手动敲入 `1-2`、`m`、`s`、`d`，而是呈现现代终端的高亮单选与多选列表。在候选主机阶段，系统将扫描到的所有物理主机与操作动作项（手动添加、跳过主机、完成配置）合并为一个流畅的单选列表，使用者通过键盘上下方向键（或 `j`/`k`）平滑移动高亮光标，按下 `Enter` 键即直接选定并触发对应分支。在选定主机后的从属共享选择阶段，系统以清晰的多选复选框呈现该主机名下的全部已挂载卷宗，光标移动至目标共享后按下 `Space` 键即可切换选中 `[x]` 或取消 `[ ]`，按下 `a` 键可一键全选或清空，按下 `Enter` 键即批量提交当前勾选的共享。在输入主机友好别名阶段，系统提供干净的受限单行文本输入，支持字符输入、退格擦除、直接回车继承主机地址作为默认别名、以及按 `Esc` 键即时放弃当前主机配置并安全返回主机候选列表。在后续的自动更新策略与守护服务部署确认阶段，系统均提供基于光标移动的高阶单选列表供直接回车选定。在整个向导过程中的任何环节按下 `Esc` 键，系统均即时擦除当前行并安全返回上一步，绝不产生脏配置。

**Why this priority**: 初始化向导是所有使用者接触产品的第一印象。彻底消灭选项代号敲击，实现与现代终端直觉高度一致的光标单选与空格多选，是扭转交互退化、建立产品专业品质的首要基石。

**Independent Test**: 在终端中执行 `automnt --init --reset`，验证候选主机列表能否通过上下方向键直接移动高亮并按 Enter 进入；验证从属共享能否通过 Space 切换勾选并按 a 全选后批量 Enter 提交；验证主机别名输入是否支持退格与回车继承默认值；验证全过程无需在键盘上手动敲入任何选项数字或字母编号。

**Acceptance Scenarios**:

1. **Given** 系统中存在活跃挂载的 SMB 卷宗，**When** 使用者执行 `automnt --init` 进入向导，**Then** 候选主机与操作动作以统一的单选列表呈现，当前选定项前显示清晰的高亮指针（如 `❯`），使用者通过上下方向键或 `j`/`k` 键移动焦点，按下 `Enter` 即可直接进入对应主机配置或执行动作（如手动添加、跳过、完成），终端无需提示使用者敲入选项编号。
2. **Given** 使用者在候选列表中选定了某台主机，**When** 系统提示输入主机友好别名，**Then** 系统进入单行受限文本输入模式；使用者输入字符后按下退格键能即时擦除字符；若使用者直接敲击 `Enter` 键，系统自动采用主机名或地址作为默认别名并进入下一步；若使用者按下 `Esc` 键，系统即刻整行擦除，输出 `(已取消)` 并安全返回主机候选列表。
3. **Given** 使用者完成别名确认，**When** 系统进入该主机名下的从属共享配置，**Then** 系统以多选复选框展示所有从属共享，使用者通过上下键移动光标，按下 `Space` 键可自由翻转单项勾选状态（`[x]` / `[ ]`），按下 `a` 键可切换全选或全不选，按下 `Enter` 键即批量完成勾选提交。
4. **Given** 使用者处于主机选择或共享多选界面，**When** 使用者按下键盘 `Esc` 键，**Then** 系统立即清除当前重绘屏幕或当前行，输出 `(已取消)` 并平稳安全回退上一级菜单，不留存任何半成品脏数据。
5. **Given** 使用者在向导末尾面对自动更新策略或守护服务部署确认，**When** 界面展示选项，**Then** 系统以单选列表展示各项选项，使用者通过上下方向键直接选定目标策略并按 `Enter` 确认，无需手工输入 `Y` 或 `n`。

## 用户故事 2 - 日常管理主菜单与全链路维护选单重构 (Priority: P1)

使用者在执行 `automnt --config` 进行日常配置维护时，不再面对复合代号提示行（如 `请选择操作 [1-1 / a / m / d / u / q]:`），而是面对一个将配置的主机顺位列表与全局管理动作有机融合的高阶交互主菜单。主菜单以清晰的光标单选列表呈现：所有已配置的主机顺位排在顶部，新增主机、调整主机顺位、删除主机、修改更新策略、保存并退出等动作紧随其后。使用者使用方向键高亮任一主机条目并回车，即可直接进入该主机的从属管理二级单选菜单（包含追加共享、批量删除共享、批量切换启用状态、返回上一级）；高亮任一动作项并回车，即可直接执行该管理功能。在新增主机时，系统以单选选单提供“扫描当前已挂载卷宗”与“手动录入新主机地址”；在调整主机顺位时，系统通过两步单选（第一步单选待移动主机 ➔ 第二步单选目标放置顺位槽位）完成调整并即时刷新排序；在修改更新策略时，系统以单选列表展示可选策略；在删除主机时，系统以单选列表展示候选主机供选定，彻底淘汰全链路中任何代号、编号或字母的手动键入。

**Why this priority**: 日常配置是使用者维护挂载目标的核心阵地。将割裂的文本提示行升级为一体化高阶选单，覆盖主菜单、二级管理菜单、新增选择、顺位调整及策略切换全链路，能彻底消除高频维护时的输入摩擦，大幅提高配置修改效率与防错能力。

**Independent Test**: 运行 `automnt --config`，验证主菜单是否整合为光标单选列表；验证进入主机后能否通过二级单选菜单流转并使用空格多选复选框批量维护共享；验证调整主机顺位是否通过两步单选流畅完成且列表即时重排；验证全流程无需键盘敲入任何代号编号。

**Acceptance Scenarios**:

1. **Given** 配置文件中已存在顺位主机，**When** 使用者执行 `automnt --config`，**Then** 主菜单将“主机顺位条目”与“新增、调顺位、删主机、更策略、保存退出”等动作项聚合为单个平滑滚动的单选列表，高亮任一主机条目按 `Enter` 即可直达该主机从属管理二级单选菜单，无需键入类似 `1-1` 的复合编号。
2. **Given** 使用者进入某主机的从属管理二级菜单，**When** 界面呈现管理操作，**Then** 系统以单选列表展示“追加共享”、“批量删除共享”、“批量切换启用状态”、“返回上一级”，使用者通过方向键高亮并按 `Enter` 即可直达对应操作，无需输入字母代号。
3. **Given** 使用者在二级菜单中选择追加共享，**When** 系统扫描到系统中已挂载的该主机新卷宗，**Then** 系统提供多选复选框供使用者使用 `Space` 键勾选目标卷宗，按 `Enter` 批量追加并自动忽略重复项；若选择批量删除或批量切换状态，同样以多选复选框呈现所有从属共享供批量勾选并回车确认。。
4. **Given** 使用者在日常管理主菜单中选择“调整主机顺位”，**When** 进入调整流程，**Then** 系统首先展示已配置主机的单选列表供使用者光标高亮并按 `Enter` 选定待移动主机；接着系统展示所有目标顺位槽位单选列表（例如 `顺位 1`、`顺位 2` 等），使用者光标移动至目标槽位按 `Enter` 确认，系统即时完成排他顺位重排并返回主菜单更新渲染展示；在此期间按下 `Esc` 键安全放弃调整。
5. **Given** 使用者在日常管理主菜单中选择“新增主机”或“修改自动更新策略”，**When** 进入对应界面，**Then** 系统分别以单选列表提供“扫描挂载卷宗 / 手动录入地址”以及`off`（关闭自动检查）、`notify`（发现任意较新版本时通知）与 `auto`（自动下载并安装较新版本）供光标直达回车选定，无需输入数字代号。
6. **Given** 使用者在日常管理主菜单或任何子菜单中按下 `Esc` 键，**Then** 系统安全回退到上级视图；在主菜单根层按下 `Esc` 键等同于放弃未保存修改并安全退出。

## 用户故事 3 - 高风险与破坏性操作的空格单选确认防呆 (Priority: P2)

使用者在执行破坏性操作（如删除指定主机、删空所有主机）时，系统不再使用简陋的纯文本 `[Y/n]` 提示，而是弹出显式的单选防呆确认对话框。对话框中默认焦点停留在安全项上，单选状态明确呈现为 `(o) 取消并返回`，而破坏性操作项明确展示为 `( ) 确认删除`。方向键仅用于在选项之间上下移动光标焦点指示符（如 `❯`），绝不直接更改单选勾选状态；使用者必须将焦点移至确认项后，显式按下 `Space` 键，单选框才翻转为 `(o) 确认删除`（同时取消项变为 `( ) 取消并返回`）；此时再按下 `Enter` 键方可执行删除。若单选框仍处于 `(o) 取消并返回` 状态时使用者敲击 `Enter` 键，或使用者在任何时刻按下 `Esc` 键，系统坚决视为安全取消并返回，绝不执行删除，彻底杜绝因误触回车键导致的配置误清空。

**Why this priority**: 终端用户极易因肌肉记忆惯性敲击回车。显式空格单选防呆机制将“焦点移动”与“状态选中”严格分离，把破坏性操作的默认阻尼拉满，是防止关键配置数据意外损毁的安全屏障。

**Independent Test**: 在日常管理中选择删除主机或删空主机，观察系统呈现的确认界面；直接按回车或按 Esc，验证删除操作被安全取消；按方向键将焦点移至确认选项但不按 Space 直接回车，验证删除操作仍被安全取消；按方向键移动焦点至确认选项并显式按下 Space 键切换单选状态后再按回车，验证删除操作被正确执行。

**Acceptance Scenarios**:

1. **Given** 使用者在日常管理中触发删除主机或清空所有主机的流程，**When** 系统进入二次确认环节，**Then** 系统呈现带有单选框标识的对话框，初始状态明确为 `(o) 取消并返回` 与 `( ) 确认删除`，光标焦点默认停留在安全取消项上。
2. **Given** 使用者处于删除确认对话框，**When** 使用者直接敲击 `Enter` 键、按下 `Esc` 键、或移动光标至确认项但未按 `Space` 键直接敲击 `Enter` 键，**Then** 系统立即取消删除操作，配置保持不变，并平稳返回上一级管理菜单。
3. **Given** 使用者处于删除确认对话框，**When** 使用者按下方向键将焦点指示符移至确认项，按下 `Space` 键使单选框翻转为 `(o) 确认删除`，然后再按下 `Enter` 键，**Then** 系统仅在内存工作副本中暂存删除操作并给出友好反馈；配置文件保持不变，直至使用者在管理主菜单显式选择“保存并退出”，此时系统统一持久化本次会话的所有变更。

## 用户故事 4 - 纯原生按键解析、长列表滚动视口与平滑原地屏幕重绘 (Priority: P2)

系统在交互期间依托操作系统标准终端接口驱动交互，无需引入任何外部第三方库。键盘输入解析器支持精准识别上箭头、下箭头、`k` 键、`j` 键、回车键（`Enter`）、空格键（`Space`）、全选键（`a`/`A`）以及取消键（`Esc`/`Ctrl+C`）。按键解析引擎在捕获到键盘取消键字节（ASCII 27）后，必须通过 50ms 超时非阻塞探测判断后续是否有连续控制字符流：若 50ms 内无后续输入，立即将其判定为独立的 `Esc` 取消事件并瞬时响应，绝不发生阻塞等待下一按键的假死现象；若存在后续转义序列，则正确解析为方向键等复合事件。在列表渲染期间，系统获取当前终端窗口可视行数，若候选列表条目过多，系统自动启用固定视口滚动机制（Rolling Viewport），仅在安全视口高度内渲染当前可视项，列表首尾显示滚动指示符（如 `▲ 向上还有 N 项`、`▼ 向下还有 N 项`），光标移动带动视口平滑滚动，绝不发生光标向上回退溢出终端顶部撕裂屏幕的问题。在选单交互期间，系统通过标准 ANSI 控制序列执行精确的原地多行擦除与重绘，交互开始时隐藏光标、交互结束或中断时恢复光标，使屏幕刷新平滑透气、零闪烁、无多余控制字符残留。

**Why this priority**: 高质量的原地重绘、完备的长列表可视窗口保护与防卡死按键序列解析是实现现代专业 TUI 的技术支撑。保证按键无漏判、长列表不撕裂屏显、独立 Esc 键瞬时响应、光标在异常中断时必定复原，是保障终端环境整洁与安全的基础。

**Independent Test**: 在真实 Terminal.app 与 iTerm2 中运行包含超过 20 个候选卷宗的向导，高频交替按下方向键、j/k 与空格键，观察视口滚动指示符与列表移动，验证终端屏幕无向上撕裂或乱码；按下独立的 Esc 键，验证系统在毫秒级内瞬时响应退出而非卡滞挂起；按下 Ctrl+C 强制退出，验证终端光标正常恢复可见且终端处于正常规范模式。

**Acceptance Scenarios**:

1. **Given** 处于单选或多选列表界面且选项数量未超终端高度，**When** 使用者按下方向键或 `j`/`k` 键，**Then** 系统仅在当前列表区域内执行标准 ANSI 原地重绘，光标平滑移动，无整屏抖动与无用空白行产生。
2. **Given** 候选主机或从属共享列表项总数超过当前终端安全可视高度（例如超过 15 项），**When** 界面呈现列表并随着使用者向下移动光标，**Then** 系统自动采用固定视口滚动窗口渲染，首尾清晰呈现滚动指示符，光标随视口滚动保持在可视区内，终端不发生光标溢出屏幕顶部的撕裂异常。
3. **Given** 处于任何交互选单或文本输入界面，**When** 使用者单独按下一次键盘 `Esc` 键，**Then** 底层解析引擎在 50ms 超时非阻塞探测确认无后续序列后立即瞬时返回取消信号，系统即刻响应并安全回退上级菜单，无任何卡顿或等待下一个按键输入的现象。
4. **Given** 处于任何交互选单界面，**When** 使用者通过 `Ctrl+C` 强制中断程序，**Then** 系统通过可靠的退出保障机制立即将终端恢复为标准规范模式并显现光标，绝不破坏使用者当前终端会话的状态。

## 用户故事 5 - 非交互管道环境优雅降级与全内存自测注入 (Priority: P3)

当程序在自动化脚本、管道重定向或非交互式终端环境下运行时，系统能够自动检测输入环境并优雅降级为标准流式行输入读取模式，绝不强制进行终端模式配置导致异常中断。同时，内置自动化自测试套件（`--self-test`）能够通过内存按键序列注入机制，无需任何人工干预即可在毫秒级内自动对全量单选直达、多选勾选、全选切换、顺位两步调整、长列表视口滚动、防呆确认及 Esc 回退逻辑进行 100% 确定性的回归覆盖。

**Why this priority**: 保持自动化测试与脚本友好性是系统长期健壮演进的生命线。确保高阶交互组件在无头环境下具备可降级性与可自测性，防止出现无法自动化验证的代码死角。

**Independent Test**: 执行 `./automnt --self-test`，验证所有新增的交互选单逻辑在全内存模拟模式下均能全绿通过；执行 `echo "" | ./automnt --init` 验证非交互环境下程序安全降级处理而非崩溃。

**Acceptance Scenarios**:

1. **Given** 程序标准输入被重定向至管道或文件，**When** 执行包含单选或多选的向导命令，**Then** 系统自动检测到非交互终端环境，安全切换至顺序行打印与文本输入降级流，无任何终端配置错误。
2. **Given** 运行程序内置自测试套件 `automnt --self-test`，**When** 执行涵盖单选直达、多选勾选、全选切换、两步顺位调整、长列表视口滚动、防呆确认与 Esc 取消的自测试用例，**Then** 测试通过纯内存模拟队列注入按键流，测试断言全部通过，退出码严格为 0。

# 边界与异常情况处理 (Edge Cases)

- **列表项数量超出当前终端窗口高度**：当扫描到的从属共享或候选主机数量较多时，原地向上移动光标可能导致滚屏错位。系统在渲染前获取当前终端可视行数，若选项超过安全高度，强制启用固定视口滚动机制（Rolling Viewport），首尾展示指示符（如 `▲ 向上还有 N 项` / `▼ 向下还有 N 项`），随着光标移动平滑滚动视口，确保终端屏幕不发生非预期撕裂。
- **独立 Esc 键与复合方向键转义序列解歧**：终端接收到取消键字节（ASCII 27）后，按键引擎启动 50ms 超时非阻塞探测。若 50ms 内无后续字节，立即判定为独立 Esc 键并瞬时触发取消回退；若后续存在控制序列，则无缝解析为方向键等复合事件，彻底杜绝单按 Esc 键终端假死挂起的现象。
- **输入流异常中断与流终止**：在终端字符捕获过程中，若输入流意外中断或接收到流结束信号（EOF/Ctrl+D），底层按键解析器立即检测流关闭并触发安全取消信号，平稳回退上一级或安全退出，杜绝死循环空转与 CPU 100% 自旋。
- **连续极速按下 Esc 键**：使用者连续按下多次 Esc 键时，系统逐层平稳回退各级菜单，行缓冲被彻底清空，不积累滞留按键事件。
- **混合选单项中的不可选禁用条目**：在向导候选主机列表中，已配置的主机显示 `[✓] 已配置` 标记且不可重复选择。若光标移动至该项并按 Enter，系统发出温和提示“该主机已完成配置”，光标保持在当前项，不破坏列表状态。

# 功能需求规范 (Requirements)

- **FR-001**: 系统 MUST 在交互式终端中的向导（`--init`）与日常管理（`--config`）全面淘汰要求使用者手动敲入选项数字编码或字母代号的命令行提示行。非交互式管道重定向下按 FR-008 降级时，允许以编号输入执行自动化流程。
- **FR-002**: 系统 MUST 在初始化向导（`--init`）中使用基于光标移动的交互式单选组件呈现候选主机列表与动作项，支持方向键与 `j`/`k` 移动高亮，按 `Enter` 键直接选定触发。
- **FR-003**: 系统 MUST 在向导与日常管理的主机从属共享选择环节，使用交互式多选复选框组件，清晰展示 `[x]` 与 `[ ]`，支持 Space 键切换单项、`a` 键全选/全不选，按 `Enter` 键批量确认提交。
- **FR-004**: 系统 MUST 在日常配置管理（`--config`）中全链路采用高阶选单：主菜单以单选整合主机顺位与全局动作；主机从属管理二级菜单以单选整合各维护动作；新增主机方式与更新策略修改均采用单选；主机顺位调整采用“两步单选（源主机 ➔ 目标槽位）”完成排他顺位重排。
- **FR-005**: 系统 MUST 在高风险/破坏性操作（如删除指定主机、清空所有主机）中采用显式空格单选确认防呆机制：初始状态默认选中 `(o) 取消并返回`，方向键仅移动焦点指示符，必须使用者显式按下 `Space` 键翻转单选框为 `(o) 确认删除` 后按 `Enter` 方可执行，未翻转直接回车或按 `Esc` 坚决视为取消。
- **FR-006**: 系统 MUST 在所有选单与输入行中，将按下键盘 `Esc` 键作为全局即时放弃并安全回退上级菜单的统一规约，整行擦除且绝不保存脏配置；按键解析引擎在捕获到取消键字节（ASCII 27）后通过 50ms 超时非阻塞探测瞬时判定独立 Esc 键，杜绝假死等待。
- **FR-007**: 系统 MUST 仅在未挂载主机地址、主机友好别名及未挂载 SMB 共享 URL 等必要场景保留单行文本输入，文本输入支持字符输入、退格擦除、默认值回车继承与 Esc 即时放弃。
- **FR-008**: 系统 MUST 在非交互式管道重定向环境下自动优雅降级为标准流式行读取模式，并支持在自动化自测试套件中通过纯内存队列注入按键流进行确定性自测。
- **FR-009**: 系统 MUST 在候选列表总数超过当前终端安全可视高度时，自动启用固定视口滚动窗口机制（Rolling Viewport），首尾显示滚动指示符，随光标移动平滑滚动视口，坚决防止光标回退溢出终端顶部撕裂屏显。

# 成功指标与业务衡量 (Success Metrics)

- **SC-001**: 交互式终端中的选单选项代号手动输入发生率彻底归零（由基准 100% 降至 **0%**）；非交互管道降级允许按 FR-008 使用编号输入。
- **SC-002**: 常用配置流转（如向导多选共享、管理菜单进入主机、主机顺位调整）的按键效率以同任务、同状态的新旧版本实测为依据持续衡量：使用相同任务、相同状态的配置副本，记录完成每项任务所需的实际按键总数，并报告每种流程的任务数量及均值（实测记录见 `sc-002-keystroke-measurement.md`），不设未经实测支撑的预设百分比目标。
- **SC-003**: 全局任何交互选单与输入行中按下 Esc 键的安全取消回退成功率达到 **100%**，且单按 Esc 键响应延迟在 50ms 阈值内无感知。
- **SC-004**: 内置全量自测试套件在全内存模拟模式下保持 **100% PASS**（退出码 0），覆盖单选直达、多选勾选、全选切换、两步顺位调整、长列表视口滚动、破坏性防呆确认与 Esc 取消全量交互场景。

# 架构假设与排除边界 (Assumptions & Exclusions)

## 架构假设 (Assumptions)

- 终端环境为 macOS 27.0+（Apple silicon arm64），原生终端仿真器（Terminal.app、iTerm2 等）均标准支持 ANSI 光标定位与擦除指令。
- 底层配置数据模型（主机配置模型、从属 SMB 共享配置模型与全局系统配置结构）完全保持不变，无需改动现有配置文件存储契约。
- 运行时主机顺位 TCP 445 端口排他探测、NetFS 静默挂载核心调度逻辑完全保持不变。

## 排除边界 (Exclusions)

- **绝不引入第三方外部 UI 库**：严禁引入 ncurses、curses 动态库或外部 Swift Package，坚守纯原生零依赖底座。
- **不变更配置文件结构与版本**：本次改造为交互表示层优化，配置文件规范版本保持稳定兼容。
- **不破坏非交互脚本的可用性**：在非交互式管道环境下保留流式行降级，保障自动化脚本调用的健壮性。
