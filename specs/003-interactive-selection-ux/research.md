# 1. 原生终端 TUI 状态机与 ANSI 转义序列体系

## 决策内容

坚持单文件纯原生零外部依赖原则，不引入 ncurses、curses 动态库或外部第三方 Package。依托 Darwin POSIX 标准终端接口（`termios`）与 ANSI X3.64 / ECMA-48 控制转义序列，构建轻量、高响应、无闪烁的原生 TUI 状态机。

## 核心转义指令标准

- 光标可见性控制：进入交互选单前输出隐藏光标指令 `\033[?25l`；选单退出（无论正常提交、Esc 取消还是 Ctrl+C 异常中断）前必定输出显现光标指令 `\033[?25h`；
- 原地擦除与重绘：渲染新一帧前，通过 `\033[NA` 精确向上回退 N 行，配合 `\033[2K`（整行清除）或 `\033[K`（清除至行尾），仅在列表有效可视高度内重绘内容；
- 终端状态安全恢复：进入交互前保存原始终端属性（`tcgetattr`），设置非规范原始模式（`c_lflag &= ~(ICANON | ECHO | ISIG)`）；利用语言级退出保障机制确保在任何退出路径（含信号中断）均执行 `tcsetattr` 还原终端。

## 替代方案评估与舍弃原因

- 引入 ncurses / curses 库：虽然提供成熟的窗口与面板抽象，但破坏了项目纯原生单文件编译架构，增加了跨平台编译标志与运行时动态链接依赖；
- 引入三方 Swift TUI 框架：违背了单一源码文件、零外部依赖的宪法级交付约束。

# 2. 独立 Esc 键 50ms 超时非阻塞解歧机制

## 决策内容

按键输入解析引擎在从标准输入读取到 ASCII 27（取消键字节）时，不执行阻塞式字符读取，而是通过 50ms 超时非阻塞探测判断后续是否有连续控制字符流。同时，在读取后续字节时同样施加非阻塞短超时保护，并兼容标准 CSI（`ESC [`）与 SS3（`ESC O`）转义序列。

## 判定状态机

- 若在 50ms 内无后续字节输入，立即将其判定为独立的 `Esc` 键取消事件，瞬时向业务层返回退出信号（`nil`），实现毫秒级无感回退；
- 若在 50ms 内检测到后续控制字节 $b_1$（兼容 $b_1 == 91$ 即 `[` 以及 $b_1 == 79$ 即 `O`），系统继续在 10ms 短超时保护下非阻塞读取后续参数字节 $b_2$，准确解析为方向键上、下等复合操作事件，绝不发生无界阻塞挂起；
- 若后续字节无法匹配已知控制序列或发生截断，安全丢弃并清空临时缓冲，防止非预期字符乱入。

## 缺陷溯源与解决效果

在历史实现中，按键解析器捕获 ASCII 27 后直接调用阻塞式的字节读取，导致使用者单按一次 Esc 键时，程序卡死等待下一个按键输入，产生严重的“终端假死”体验。50ms 超时探测机制彻底消除了该问题，配合 $b_2$ 短超时保护与 SS3 模式兼容，确保在各种终端仿真器（包括 tmux、screen 等）下方向键均能 100% 稳定响应。

# 3. 长列表固定视口滚动窗口机制（Rolling Viewport）

## 决策内容

通过系统调用（`ioctl` 读取 `winsize`）动态获取当前终端窗口的实际可视行数，并设立安全阈值（默认视口最大可见行数 `maxVisibleRows = 12`，或 `min(12, terminalHeight - 6)`）。当候选项目总数超过安全视口时，启用固定视口滚动窗口。

## 滚动窗口算法模型与固定行数预算

- 视口状态维护：维护 `windowStartIndex`（视口起始索引）与 `cursorIndex`（当前光标绝对索引）；
- 视口初始对齐：若存在非零默认索引 `defaultIndex`，初始化时动态计算 `startIndex`，保证光标首帧必在视口可视切片内；
- 固定行数预算（Fixed Line Budget）：为顶部和底部滚动指示符设立固定占位槽位。若不可滚动，输出占位清除行保持物理总行数 $R$ 恒定不变，确保 `\033[RA` 向上回退物理位移绝无累积误差，杜绝终端画面垂直漂移与历史屏幕撕裂。

# 4. 五大交互范式的交互表示层规范

## 范式一：光标单选直达（Cursor Direct Radio）

- 适用场景：向导候选主机选择、日常管理主菜单、主机从属二级管理菜单、新增主机方式选择；
- 行为契约：上下方向键或 `j`/`k` 移动焦点指针（`❯`），按下 `Enter` 键即直接选定当前高亮项并触发流转，按下 `Esc` 键整行擦除并安全回退。

## 范式二：空格单选确认防呆（Explicit Radio with Space）

- 适用场景：高风险与破坏性操作（删除主机、清空所有主机、重置配置）；
- 行为契约：
  - 初始状态：焦点停留在安全项，状态明确为 `(o) 取消并返回` 与 `( ) 确认删除`；
  - 焦点移动与选中状态彻底正交：上下方向键仅在选项间移动焦点指针（`❯`），绝对不改变单选勾选状态；
  - 显式翻转：必须显式按下 `Space` 键，目标项才翻转为 `(o)`，原选中项变为 `( )`；
  - 执行判定：只有单选框为 `(o) 确认删除` 时按 `Enter` 才执行操作；若仍为 `(o) 取消并返回` 时按 `Enter`、或未按 Space 直接按 `Enter`、或在任何时刻按 `Esc`，坚决判定为安全取消。

## 范式三：空格多选再回车确认（Checkbox Multiple Selection）

- 适用场景：主机从属共享多选添加、批量删除从属共享、批量启停从属共享；
- 行为契约：上下方向键或 `j`/`k` 移动焦点；按下 `Space` 键翻转当前项选中状态（`[x]` / `[ ]`）；按下 `a`/`A` 键智能切换全选或全清空；按下 `Enter` 键批量提交当前勾选集合；按下 `Esc` 键放弃并安全回退。

## 范式四：全局 Esc 即时安全回退（Universal Instant Esc）

- 适用场景：全系统所有单选、多选、确认弹窗及文本输入界面；
- 行为契约：按下 `Esc` 键即刻整行擦除并输出 `(已取消)`，返回 `nil`，调用方平稳安全回退至上一级菜单，绝不持久化任何脏配置或半成品数据。

## 范式五：受限单行文本输入（Constrained Line Prompt）

- 适用场景：未挂载新主机地址录入、主机友好别名录入、未挂载 SMB 共享 URL 录入；
- 行为契约：支持字符输入与退格键即时擦除；支持默认值回车直接继承；按 `Esc` 键即刻整行清除并安全放弃。

# 5. 非交互环境流式降级与全内存按键序列注入机制

## 降级判定与行为

- 通过 `isatty(STDIN_FILENO) == 0` 判定管道重定向或无头脚本调用；
- 非交互环境下坚决禁止调用 `tcsetattr` 配置原始模式，自动切换为标准的流式行打印与 `readLine()` 读取降级模式。

## 确定性自动化测试注入

- 在 `TerminalUI` 控制器中内置内存按键队列模拟接口（如 `mockKeySequence: [KeyAction]?`）；
- 当注入模拟队列时，`readKey()` 优先从内存队列中弹出按键事件，无需人工介入终端，即可在毫秒级内全自动执行光标移动、空格勾选、全选、两步顺位调整、视口滚动、防呆确认与 Esc 放弃的全量自测断言。
