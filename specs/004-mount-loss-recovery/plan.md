# 方案概述与技术上下文

## 概述与核心路径

本计划面向 Feature 004（挂载丢失自动恢复），在不引入常驻等待进程与周期轮询的前提下，解决“远程主机不稳定丢挂载后非技术使用者只能重启电脑”的核心症状，同时以三重信号判别把使用者健康弹出的意图保护在会话级抑制语义内。核心路径：

1. **事件唤醒**（登录 / 网络配置变化 / 挂载命名空间变化）→ 后台服务短命执行，跑完即退；
2. **快照判定**：读挂载表（复用既有 `MNT_NOWAIT` 非阻塞快照）+ 两本自账（**新建**：挂载账由配置与快照推导、清理账由清理动作写入）+ 卷失效探测（**新建**：在快照之上实现非阻塞失效判定，不得引入 `stat()` 阻塞路径）；
3. **三重信号判别**：卷在表但失效（网络丢失）→ 清理并纳入恢复；卷缺失且系产品清理所致 → 纳入恢复；卷缺失且系健康时被使用者弹出 → 会话级抑制（保守方向：信号缺失即抑制）；
4. **有界幂等重挂**：复用既有主机探活、静默挂载与钥匙串凭据，有限次尝试；
5. **兜底可见**：实际恢复失败 → 系统通知（每轮至多一条）；会话抑制静默且不消耗通知计数；配置菜单“立即重新挂载”入口始终可用。

会话级抑制按维护者裁决执行：持续至网络上下文变化或重新登录（先到者）解禁；评估阶段的备选 C（周期兜底）明确排除在外，仅作为未来实测覆盖不足时的重新评估入口。

## 技术上下文规范

- **开发语言与编译器**: Swift 6.4（macOS SDK 27.0+，Apple silicon arm64，原生 `/usr/bin/swiftc -O`）；
- **核心依赖**: 纯 macOS 原生标准库（`Darwin`、`Foundation`、`NetFS`、系统通知与钥匙串能力），严格禁止引入第三方 Swift Package 或动态库依赖；
- **配置与状态持久化**: 活动配置 `automnt.plist` 仅新增“自动恢复开关”字段（默认启用，随既有原地升舱迁移）；会话抑制/待恢复状态存放于**独立附属状态文件**（0600 权限、按卷粒度、可丢弃重建），不构成第二份活动配置；
- **自动化测试**: 内置自测试套件（`./automnt --self-test`，2026-10-05 实跑核实 161 项）扩展恢复判定/状态机断言；交互过程用伪终端记录；SC-001/SC-002 的挂载语义验收以**实机真实挂载对照实验**为准（证据纪律标注环境）；
- **目标运行平台**: macOS 27.0+（Apple silicon arm64）；
- **项目交付形态**: 单源码文件（`automnt.swift`）+ 最高优化预编译二进制（`automnt`）；
- **性能与响应目标**: 事件唤醒后**当轮评估内**完成恢复判定与尝试（clarify Q1 口径，无钟表时限）；有界重试沿用现有窗口（≤3 次、总窗口 ≤10s 量级）；
- **架构约束**: 无常驻等待进程、无固定周期强制唤醒（FR-009 / Constitution II）；零凭据交互；误覆盖手动弹出 = 0；恢复状态可丢弃重建；**不提供任何弹出/卸载功能**（产品能力边界，维护者裁定；判别所需的“弹出”一律指识别使用者弹出事件，不由本产品发起）。

## 宪法原则审查（Phase 0 前）

- **原则 I（配置只能来自真实探测或显式输入）**: **符合**。恢复只重挂既有配置中的启用卷，不产生任何新业务配置；状态文件零业务数据；验收配置全部由程序生成或为真实既有配置，严禁手工伪造。
- **原则 II（不得引入第二个常驻运行进程）**: **符合**。恢复判定为事件唤醒的短命执行，明确禁止常驻等待进程与固定周期轮询（FR-009 就是本特性设计红线）；方案 C 的周期形态已被规格排除。
- **原则 III（单一活动配置来源）**: **符合**。附属状态文件是可丢弃的运行时状态（非可独立编辑的活动配置），不与 `automnt.plist` 构成双活动配置；恢复执行读取的仍是同一份活动配置。
- **原则 IV（版本与发布产物同源）**: **符合**。版本 SSOT 仍为 `automntVersion` 单点；新增配置字段随原地升舱写入，初始特性 MINOR 3.3.0 已完成，通知修复 PATCH 3.3.1 与本次采集／诊断修复 PATCH 3.3.2 均已正式安装；按项目纪律，本次不做任何 GitHub Release。
- **凭据约束**: **设计符合，实机未闭合**。恢复由系统钥匙串静默提供 SMB 凭据，状态与日志零凭据；实机替换临时签名产物触发网络卷访问授权，不能把它归为已满足零打扰。

# 技术设计与演进路线

## Phase 0: 技术调研与关键决策（research.md）

1. **判别信号选型** → 决策：三重信号组合（挂载表存在性 + **新建**失效探测；**新建**两本自账；卸载前丢失证据时间线作**尽力而为**增强），信号缺失时保守抑制。理由：评估 72h 实测证明“丢失≠卸载”、DiskArbitration 无成因字段；替代方案（事件判因=无字段、常驻观察=违宪、纯日志=版本漂移单点风险）被拒。
2. **恢复状态持久载体** → 决策：独立附属状态文件（0600、按卷、可丢弃重建）。理由：不改活动配置结构（排除边界）且会话抑制需跨短命执行持久；替代（配置新键=结构变更被禁、纯内存=跨唤醒丢失、注册表/第三方=新增依赖）被拒。
3. **事件源扩展** → 决策：复用 `RunAtLoad`+`WatchPaths`，新增挂载命名空间事件（系统级“挂载时启动作业”键与挂载目录增删监听）。理由：官方事件机制、零轮询；替代（周期 `StartInterval`=违 FR-009 即方案 C、DiskArbitration 常驻观察=违宪）被拒；`WatchPaths` 官方竞态警示作为既有风险项列入评估修复建议。
4. **恢复执行链路** → 决策：复用**确实存在**的既有能力——主机探活（TCP 445）、NetFS 静默挂载、钥匙串凭据与 EvaluationRetryRunner 有界重试。替代：独立恢复器=重复实现。
5. **死卷清理联动** → 决策：复用既有强制卸载工具函数（`forceUnmountWithTimeout`）作为执行手段，但**新建**“失效探测触发清理”的调用路径与清理账写入（现状该函数仅有一个调用点、触发条件为源不匹配，从不因失效触发）。
6. **兜底通知** → 决策：复用既有系统通知通道，恢复判定轮去重（每轮至多一条）；菜单入口为第二通道。替代：仅日志=发现性不足、菜单-only=通知盲区。
7. **会话边界** → 决策：**新建**网络上下文身份判定（叠加登录会话，先到者解禁）。理由：现有 `NetworkProfile` 是遗留结构且被迁移清空（`configNeedsMigration` 对非空 profiles 恒真），`SystemConfiguration` 虽被 `import` 但源码未调用其任何 API（无 `SCNetwork*`/`SCDynamicStore` 调用点），**不存在可复用的网络身份机制**；候选实现为系统网络状态查询（如动态存储/路由/接口身份快照），须在实现任务中定型。替代：时间窗阈值=拍脑袋且不可测。
8. **验收实验设计** → 决策：实机真实挂载对照实验（断网-恢复 / 真实弹出 / 修复弹出三组），伪终端记录交互，全程证据纪律标注；隔离环境仅作辅助。替代：仅伪终端=验证不了内核挂载语义。
9. **信号降级路径** → 决策：任何信号不可读即保守抑制 + 兜底入口，状态异常不改变方向。
