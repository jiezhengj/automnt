**Artifact**: 端到端快速验证指南（End-to-End Quickstart Guide）

**Feature ID**: `004-mount-loss-recovery`

**Created**: 2026-10-05

# 前置环境准备

- 运行平台：macOS 27.0+（Apple silicon arm64）；真实 SMB 挂载就绪（场景 1–5 依赖真实卷，**实验会触碰真实挂载，执行时机需维护者批准**）。
- 编译生成最新二进制：
  ```bash
  xcrun --sdk macosx swiftc -O -target arm64-apple-macos27.0 -o ./automnt automnt.swift
  ```
- 验证自测试套件基线：
  ```bash
  ./automnt --self-test
  ```
- **证据纪律声明**：每个场景必须标注执行环境（实机真实挂载 / 伪终端记录 / 隔离环境辅助）；挂载与卸载语义只有实机场景可作有效证据；隔离环境不得冒充实机；每次实机操作前后记录活动配置摘要，确认运行前后一致：
  ```bash
  shasum -a 256 "$HOME/Library/Application Support/automnt/automnt.plist"
  ```

# 场景 1：实机断网-恢复后挂载自动回挂（SC-001，实机真实挂载）

## 验证步骤

1. 记录前置：`automnt.plist` SHA-256；确认目标卷当前健康挂载（Finder 可用）。
2. 制造丢失：断开远程主机的网络路径（如关闭异地互联客户端/拔除网络），观察目标卷变为失效或丢失状态（可辅助取证：`log show --last 5m --predicate 'eventMessage CONTAINS "reconnect"'` 出现会话重连记录、卷仍留在挂载表或已消失——两种形态皆可）。
3. 恢复网络路径，等待系统产生网络/挂载事件唤醒服务。
4. **预期**：事件唤醒后的当轮评估内卷自动回到可用状态；全程零人工操作、零对话框、零重启；恢复尝试次数有界。
5. **SC-001 轮次要求**：按 SC-001 重复步骤 2–4 **≥3 轮**，逐轮记录“是否在事件当轮恢复”；恢复率须为 100%（N≥3）。单轮结果不构成 SC-001 证据。
6. 复核 `automnt.plist` SHA-256 前后一致。

# 场景 2：健康弹出会话内零重挂，边界后解禁恢复（SC-002 红线，实机真实挂载）

## 验证步骤

0. **特性前基线取证（SC-002 对照）**：先用改造前的旧二进制（或回滚到本特性前的工作树）复现一次“健康弹出 → 观察是否被自动重挂”，记录结果作为基线。这是 0 次红线的对照证据——说明该保护是特性带来的改善，而非现状本就具备。
1. 确认目标卷健康挂载后，从 Finder 弹出该卷（或 `diskutil unmount`）。
2. 触发若干**确非边界**的事件（插拔移动存储、对另一卷执行挂载/卸载——这些只改变挂载命名空间，不改变默认路由/网关标识与活动接口集合，属契约 §1 事件源可覆盖者；睡眠唤醒不在事件源内，不得用作本步骤）。**不得使用“切换 WiFi”“拔插网络”**：按 spec §Assumptions 的边界变化判据，它们会改变活动接口集合或路由/网关标识，本身即构成边界事件，会把本步骤变成“边界后已解禁”，无法检验红线。观察并记录：**卷在本可达会话内始终不被自动重挂**（等待时间不限，SC-002 = 0 次）。
3. 制造会话边界：按 spec §Assumptions 的判据改变网络上下文（如切换到不同网络并伴随默认路由/网关标识变化），或退出重新登录（先到者）。
4. **预期**：边界后该卷解除抑制，主机可达的下一次事件评估中自动恢复挂载（会话级语义，维护者裁决）。
5. 复核活动配置 SHA-256 前后一致。

# 场景 3：修复性弹出（弹掉死卷）后允许恢复（FR-003，实机真实挂载）

## 验证步骤

1. 断开远程主机网络，使目标卷进入失效/死卷状态。
2. 在断网期间从 Finder 弹出该死卷（记录动作；若 Finder 拒绝弹出死卷，如实记录该边界现象——本身即对照实验输出之一）。
3. 恢复网络路径，等待事件唤醒。
4. **预期**：修复性弹出不进入会话抑制，主机可达后卷自动恢复挂载（与场景 2 的“健康弹出不恢复”形成对照）。
5. 复核活动配置 SHA-256 前后一致。

# 场景 4：恢复失败的兜底：通知与“立即重新挂载”（FR-007，实机）

## 验证步骤

1. 构造失败：临时断开主机使恢复判定轮失败（`host-unreachable`），或使用程序生成的指向不可达主机的共享配置。
2. 触发一次事件评估。
3. **预期**：系统通知恰好一条（标题字面 `automnt：挂载未自动恢复`），无通知轰炸；通知或 `automnt --config` 主菜单中的 `立即重新挂载` 可用。
4. 恢复主机可达后，按通知指引在 `automnt --config` 主菜单选择 `立即重新挂载` 执行：卷挂载成功，菜单保持可用。
5. 复核活动配置 SHA-256 前后一致；状态文件仅程序改写（`mount-recovery-state.plist`，0600）。
6. **SC-004 验收**：在**步骤 1–4 的“挂载丢失 → 恢复可用”窗口内**全程记录使用者动作清单，确认 **0 次命令输入、0 次重启、0 次凭据/登录对话框**（对照 baseline 的“需重启或需敲命令”路径），并记录所用入口（通知指引 → `--config` 菜单 `立即重新挂载`）。文档查阅与否不作计分项。

# 场景 5：开关回落与状态可丢弃（FR-008 / FR-010，实机 + 隔离辅助）

## 验证步骤

1. 在 `automnt --config` 中关闭自动恢复开关（`auto_mount_recovery = false`）并**选择“保存并退出”**（开关仅在保存并退出时才落盘并再生服务定义；切换瞬间不改动；Esc 退出则开关与服务定义均不变），制造一次卷缺失并触发事件。同时核验服务定义事件源已回落为“登录 + 网络配置变化”两种。
2. **预期**：不执行自动恢复（回落基线行为），但 `立即重新挂载` 手动入口仍可用；基线评估链路（登录/网络变化）不受影响。
3. 删除附属状态文件 `mount-recovery-state.plist`（或写入损坏内容），再触发事件。
4. **预期**：状态按保守方向重建/丢弃，**绝不**因状态异常产生自动重挂（被抑制卷依旧不被恢复）；恢复功能其余场景正常。
5. 重新打开开关，确认行为恢复；复核活动配置 SHA-256 前后一致。

# 场景 6：事件驱动与服务定义验证（SC-005，本地检查 + 日志时间线）

## 验证步骤

1. 检查已安装的服务定义无周期启动键：
   ```bash
   plutil -p "$HOME/Library/LaunchAgents/com.user.automnt.plist" | grep -Ec 'StartInterval|StartCalendarInterval' || true   # 预期输出 0（计数为 0 时 grep 退出码为 1，脚本需容错）
   ```
   （该断言同时覆盖 `StartInterval` 与 `StartCalendarInterval` 等固定周期强制唤醒键；任一存在即失败。）
2. 检查无常驻进程：恢复事件之外无 automnt 常驻实例（`pgrep -fl automnt` 在非评估时段无结果）。
3. 场景 1–3 的执行日志时间线应呈现“事件 → 短命运行 → 退出”形态（`log show`/程序日志），无任何周期性自发运行记录。
4. **既有安装收敛核验**：在开关为 `true` 的既有安装上，通过交互式入口（`--config` 保存并退出或 `--install`）触发事件源收敛后，确认服务定义事件源为三类（登录 + 网络配置变化 + 挂载命名空间）；重复执行不得产生无谓重载（幂等）。
5. **预期**：恢复全部由事件驱动，零轮询、零常驻；既有安装与全新安装的事件源集合一致。

# 场景 7：自测试套件与零打扰（SC-003，本地 + 实机观察）

## 验证步骤

1. 运行 `./automnt --self-test`，确认恢复判定/状态机/降级路径断言全部通过且退出码 0。
2. 实机执行场景 1/3/4 全程：凭据/登录对话框出现次数为 0；同一卷重复挂载次数为 0（幂等）；单卷失败后无持续后台重试（日志中尝试次数有界）。
3. **预期**：满足 SC-003 三项 0 指标。

# 环境与证据说明

- 场景 1–5 为**实机真实挂载**场景（有效的挂载/卸载语义证据），需维护者批准时机；场景 6–7 为本地检查与自测（可在任意环境执行）。
- 伪终端记录可用于捕捉交互与通知文案字面（如场景 4 的通知标题），但不得作为挂载恢复/抑制语义的证据；隔离环境仅用于辅助流程观察。
- 场景 2/3 构成“健康弹出 vs 修复弹出”的对照实验，正是评估阶段预留的验收校准项（见 research.md §8）。
