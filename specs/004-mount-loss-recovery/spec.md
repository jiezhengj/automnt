# 用户场景与验收测试

## 用户故事 1 - 远程主机闪断后挂载自动恢复 (Priority: P1)

使用者的远程主机（如异地互联环境）不稳定，网络闪断导致共享卷失效或丢失。主机重新可达后，automnt 自动把配置启用且此前已挂载的卷重新挂上——使用者全程零操作，不再需要重启电脑，也不需要知道任何命令。

**Why this priority**: 这是本特性的核心症状本身（维护者转述的用户痛点：丢了挂载、只能重启），解决它即交付主要价值。

**Independent Test**: 可通过“断网-恢复”对照实验完整验证：断开主机使卷失效/丢失 → 恢复主机可达 → 观察卷在零人工操作下自动恢复为可用状态。

**Acceptance Scenarios**:

1. **Given** 配置启用的卷处于健康挂载且主机可达，**When** 主机断连导致该卷失效或丢失，**Then** 系统不将其视为使用者弃用，保持其“可自动恢复”资格。
2. **Given** 卷因主机断连而失效或丢失，**When** 主机重新可达且系统被任一事件唤醒评估，**Then** 卷被自动重新挂载，使用者无需任何操作即可使用。
3. **Given** 卷已存在有效挂载，**When** 恢复逻辑运行，**Then** 不重复挂载（幂等），不弹出任何对话框。
4. **Given** 恢复尝试因主机仍不可达或共享拒绝连接而失败，**When** 系统完成有限次有界尝试，**Then** 不产生持续后台重试，且后续主机可达时仍可再次恢复。

## 用户故事 2 - 手动弹出的意图尊重（会话级抑制）(Priority: P1)

使用者从 Finder 手动弹出健康共享（希望它别再自动回来）。automnt 在本可达会话内绝不重新挂载该卷——重现 3.0.0 之前的“没一会儿又被重挂”必须为零；而当网络上下文变化或重新登录（先到者为准）后，该卷重新纳入自动恢复。若使用者弹出的是已失效的死卷（修复动作而非弃用意图），系统允许其在主机可达后恢复。

**Why this priority**: “误覆盖手动弹出 = 0”是历史上导致移除旧方案的硬红线；与 P1 的自动恢复互为约束，缺一则特性不可上线。

**Independent Test**: 可独立验证：健康卷弹出后跨多轮事件唤醒等待，确认零重挂；随后触发网络上下文变化，确认该卷重新具备可恢复资格并能被恢复。

**Acceptance Scenarios**:

1. **Given** 卷健康挂载中，**When** 使用者弹出该卷，**Then** 本可达会话内不发生任何自动重挂（期间发生其他无关挂载事件亦然）。
2. **Given** 卷已被使用者弹出且处于会话抑制中，**When** 网络上下文变化或重新登录发生（先到者为准），**Then** 抑制解除，该卷重新纳入自动恢复，并在主机可达的下一次事件评估中恢复挂载。
3. **Given** 卷已因主机断连失效，**When** 使用者将该死卷弹出（修复动作），**Then** 不判为弃用意图，主机可达后允许自动恢复。
4. **Given** 任何卷缺失，**When** 判定所需信号缺失或不可读，**Then** 走保守路径（本会话不重挂，交由兜底引导），绝不误伤使用者意图。

## 用户故事 3 - 恢复失败或被抑制时的傻瓜化兜底 (Priority: P2)

自动恢复未能奏效（如凭据失效、主机再次断连、或该卷正处于会话抑制）时，使用者会收到一条纯文本系统通知（列出未恢复的共享并指引恢复入口），并在配置菜单中点击“立即重新挂载”完成恢复——始终不需要命令行知识。通知不携带可点击动作，菜单入口是唯一的一键恢复路径。

**Why this priority**: 这是“傻瓜化”承诺的最后一层，覆盖评估中确认的全部残余死角；核心恢复（P1）上线后若无此层，残余场景仍会退化为“只有重启才行”。

**Independent Test**: 可独立验证：构造自动恢复失败或卷被抑制的场景，确认通知/菜单入口出现且点击后触发一轮挂载并成功（主机可达时）。

**Acceptance Scenarios**:

1. **Given** 配置启用的卷缺失且无法自动恢复（失败或被抑制），**When** 系统完成一轮事件评估，**Then** 向使用者提供可见恢复入口（一条纯文本系统通知列出未恢复的共享，且配置菜单含可执行的“立即重新挂载”）。
2. **Given** 使用者通过可见入口触发恢复，**When** 主机可达，**Then** 卷挂载成功，无需任何后续步骤。
3. **Given** 恢复失败持续存在，**When** 多轮事件评估发生，**Then** 通知不形成轰炸（每轮判定至多一条，内容可合并；**且同一卷在同一可达会话内的通知受会话级上限约束**，不得每轮重复轰炸）。

# 边界与异常情况处理 (Edge Cases)

- 主机长时间离线、期间多次事件唤醒：不执行挂载（主机不可达），会话抑制与待恢复状态不丢失；恢复窗口在可达后的事件评估中按判别信号执行或保守跳过。
- 使用者在恢复成功后再次弹出：视为一次新的健康弹出，重新建立本会话抑制。
- 凭据失效导致恢复失败：有限次有界尝试后停止并转通知；全程不弹出凭据/登录对话框；不形成持续网络重试。
- 睡眠唤醒、快速连续断网、恢复抖动：同一会话内多次“丢失→恢复”循环只产生有界尝试，不产生挂载-掉载风暴（判据见 SC-003）。
- 判定信号随系统版本升级不可用/漂移：自动降级为保守路径（不重挂）+ 兜底入口，恢复功能不因此中断其余场景。
- 恢复状态丢失或损坏：以挂载表现状安全重建，缺失状态按保守方向处理；任何状态丢失都不得导致覆盖使用者弹出意图。
- 挂载点残留或历史污染（含历史 -1 后缀）：复用既有标准挂载点净化，恢复不产生重复或漂移挂载点。
- 零事件角落（主机进程崩溃且本地网络配置未变化、会话最终死亡而无任何事件）：留待下一次任意事件、重新登录或手动入口恢复；作为已知残余记录在案（评估阶段备选 C——周期兜底——即针对此角落，未纳入本规格）。
- 使用者在恢复进行中手动挂载同一卷：幂等处理，不产生重复挂载。
- 开关被关闭：行为回落至现状（仅登录与网络配置变化时评估），不产生半恢复状态。

# 功能需求规范 (Requirements)

## Functional Requirements

- **FR-001**: 系统 MUST 在配置启用的卷因主机或网络不可达而失效/丢失后，于主机重新可达的下一次事件评估中自动恢复该卷的挂载，全程无需使用者操作。
- **FR-002**: 系统 MUST 对“卷缺失/失效”按来源差异化处理：① 卷仍在但已失效（网络丢失）→ 清理死卷并纳入恢复；② 卷缺失且系产品自身清理死卷所致 → 纳入恢复；③ 卷缺失且系使用者在卷健康时弹出（存在“曾健康挂载”记录）→ 本可达会话内不恢复（会话级抑制）；④ 卷缺失且**在状态可读的前提下从未有过“曾健康挂载”记录**（全新安装、新加入的启用卷）→ 不属于使用者弃用，MUST 按基线段既有挂载范围处理并在主机可达时挂载，MUST NOT 因此进入会话抑制。任一原因导致的成功挂载 MUST 清除该卷的 `suppressed` 条目。**“从未有过记录”与“信号不可读”是两个不同前提**：前者要求状态文件可读且该卷确无记录，才适用 ④；后者按 FR-010 走保守路径，MUST NOT 因状态不可读而被当作 ④。
- **FR-003**: 系统 MUST **尽力区分**“卷失效后的修复性弹出”与“健康时的弃用性弹出”：前者在主机可达后允许自动恢复，后者适用会话级抑制；当区分所需证据不可用时，MUST 按弃用性弹出处理（保守方向，允许少恢复、绝不覆盖意图）。
- **FR-004**: 会话级抑制 MUST 持续至“网络上下文变化或重新登录（先到者为准）”后解除，该卷重新纳入自动恢复（维护者 2026-10-05 裁决语义）。
- **FR-005**: 恢复尝试 MUST 有界且幂等：失败不形成持续后台重试；已挂载的卷 MUST NOT 被重复挂载（重试边界数值见 `contracts/mount-recovery-contract.md` §3）。
- **FR-006**: 恢复路径 MUST NOT 触发任何凭据或登录对话框；凭据仅由系统钥匙串静默提供。
- **FR-007**: 系统 MUST 在自动恢复无法完成或卷被抑制时提供可见兜底：一条**纯文本系统通知**（说明哪些共享未恢复并指引恢复入口；每轮事件评估至多一条），以及配置菜单中可点击执行的“立即重新挂载”入口（**唯一的一键恢复路径**）。
- **FR-008**: 自动恢复行为 MUST 可通过配置开关启停，默认启用；关闭后行为回落至现状（仅登录与网络配置变化时评估），且配置菜单中的“立即重新挂载”手动入口 MUST 仍然可用——此时该入口的语义为**基线段挂载评估**（不全量执行自动恢复判定与会话抑制），即关闭开关不剥夺手动恢复能力，也不因此启用自动恢复逻辑。
- **FR-009**: 恢复判定 MUST 由外部事件唤醒的短命运行完成，**自动**触发源 MUST 且仅 MUST 为以下三类：① 登录；② 系统网络配置变化；③ 挂载命名空间变化（挂载发生与挂载目录增删）。系统 MUST NOT 引入常驻等待进程，MUST NOT 引入固定周期强制唤醒（本条约束自动唤醒；FR-007 的菜单手动入口为使用者显式动作，不属于自动触发源）（Constitution II 与 3.0.0 事件驱动设计承诺）；服务定义中的事件源集合与开关状态的对应关系见 `contracts/mount-recovery-contract.md` §5。
- **FR-010**: 恢复状态（会话抑制/待恢复）MUST 遵循“可丢弃重建”原则：**“信号缺失”特指信号不可读、状态文件损坏、schemaVersion 未知或解析失败**；此时 MUST 走保守路径（该卷本会话不自动重挂，交由兜底入口），任何状态异常 MUST NOT 导致覆盖使用者弹出意图。状态文件**完全不存在**（全新安装/首次运行）不属“损坏”，按 FR-002④ 正常挂载。状态损坏 MUST NOT 被解释为 FR-002④ 的“从未挂载过”。

## 关键实体 (Key Entities)

- **卷恢复状态**: 每个配置启用卷的自动恢复资格与当前状态（已挂载 / 丢失待恢复 / 会话抑制），绑定所属主机与会话边界；状态可丢弃重建（FR-010）。
- **恢复尝试记录**: 某卷一次恢复尝试的时间、结果类别（成功 / 主机不可达 / 共享拒绝 / 凭据失败）与有界重试计数；用于避免重试风暴与通知去重。

# 成功指标与业务衡量 (Success Metrics)

- **SC-001**: 断网-恢复对照实验（**实机真实挂载环境**，交互过程以伪终端记录并如实标注证据类别）中，主机恢复可达后无需任何用户操作即自动恢复挂载，**≥3 轮实验中每轮均在事件当轮恢复（恢复率 100%，N≥3）**；恢复时效口径为**事件唤醒后的当轮评估内完成**，不设钟表时限（零事件角落按边界条款由下次事件/重新登录/手动入口兜底）（baseline：今天为 0%——需重启电脑或手动执行挂载命令）。
- **SC-002**: 使用者在卷健康时弹出后，该卷在本可达会话内（会话与边界判据见 §Assumptions）被自动重新挂载的次数为 **0**（硬性红线；3.0.0 之前为“很快即被重挂”；3.2.0 现状**未验证**——源码中不存在弹出/抑制追踪机制，本特性须由 T018 场景 2 的对照实验取得基线并确认 0 次；任何回归即失败）。
- **SC-003**: 恢复全程对使用者零打扰：凭据/登录对话框弹出 **0** 次；重复挂载 **0** 次；单卷恢复失败后的后台尝试有界且不产生持续重试。
- **SC-004**: 受影响使用者从“挂载丢失”到“恢复可用”的全过程中，可观测动作计数为 **0 次命令输入、0 次重启、0 次凭据/登录对话框**（现场验收记录动作清单；对照 baseline 的“需重启或需敲命令”路径）。
- **SC-005**: 后台恢复机制保持事件驱动：不引入常驻等待进程与固定周期强制唤醒（可通过服务安装定义与运行行为验证）。

# 架构假设与排除边界 (Assumptions & Exclusions)

## 架构假设 (Assumptions)

- 会话边界为**新建**能力（现状不存在可复用的网络身份机制：`NetworkProfile` 为遗留结构且被迁移清空；`SystemConfiguration` 虽被 `import`，但源码中未调用其任何 API）：以**系统网络状态身份快照**（当前网络接口/路由/网关组合的稳定标识）为网络上下文，叠加登录会话纪元；任一变化即构成边界事件，先到者解禁抑制。该定义在规格层面钉死，实现候选机制不改变此语义。
- **“可达会话”定义**：指从一次登录（或一次边界解禁）起，到下一次边界事件为止的区间；区间内判定该卷处于会话抑制状态。**边界变化判据（MUST 可判定）**：网络上下文身份快照的构成要素集合发生**任一要素的标识变化或集合增减**（例如默认路由的网关标识改变、活动接口集合改变、或从无网络变为有网络）即构成边界事件；**仅链路可达性抖动或同一接口上不改变路由/网关标识的重连不构成边界**。该判据是实现可测性的硬约束，T004 必须据此定型并断言。
- 会话抑制与待恢复状态按卷粒度、跨服务唤醒持久保存；其最小持久载体在 plan 阶段审查（配置数据模型既有结构零变更约束）。
- 自动恢复开关为新增配置项，默认启用；配置升级走既有原地升舱。
- 能力来源须区分：**复用**既有——主机探活（TCP 445）、静默挂载（NetFS；凭据由系统钥匙串经 NetFS **隐式**提供，产品自身无钥匙串代码）、系统通知通道、非阻塞挂载表快照；**新建**——卷失效探测（现状只有字符串级“已挂载即健康”判定）、清理账与“失效触发清理”路径（现状强制卸载仅有一个源不匹配调用点）、网络上下文身份判定（见上条）、挂载账字段（`everHealthyMounted`）。
- 判别可行性基于评估阶段 72 小时实测取证：**仅丢失侧已验证**（网络丢失不产生卸载，挂载全程在表）；**卸载侧（健康弹出的干净卸载形状）样本未捕获，属未验证项**，待需维护者批准时机的对照实验确认；SC-001/SC-002 的验收证据以“真实弹出 + 真实断网”对照实验为准（实机真实挂载、伪终端记录交互、按项目证据纪律标注环境；触碰真实挂载，需维护者批准时机）；隔离环境仅用于交互流程的辅助记录，不作为挂载/卸载语义的有效证据。
- 症状个案根因（缺失/死卷 vs 凭据失效）与问题规模数据在实施期补充，不阻塞本规格。

## 排除边界 (Exclusions)
