# 稳定签名与升级授权连续性

依据宪法 V（2.1.1），运行产物必须保持可验证的稳定身份。维护者只有免费 Apple 账号，已授权参考 MacsyZones 固定 Apple Development 身份用于本机验证；Developer ID Application 不再作为本机实施的唯一前置。免费开发签名的本机结果不等于其他设备分发、Gatekeeper、公证或所有升级用户已验收。

# 身份与校验方案

本机使用 MacsyZones 已使用的 Apple Development 证书和 Team，通过钥匙串签名，不导出私钥、不把个人账号信息写入项目。代码标识固定为 `automnt`，沿用现有安装标识；不复用 MacsyZones 的 Bundle ID。签名证书通过发布环境变量提供，实际选取须核对参考项目使用身份。

安装与更新使用 Security 框架检查严格完整性、Apple 信任锚、固定 `automnt` 标识及 Apple Development / Developer ID Application 证书类别。首次可信安装随后由已安装程序的 Designated Requirement 约束升级候选；其他 Team、其他标识、未签名、临时签名及不兼容候选不能替换。检查先于运行候选 `--version`，该等待上限 2 秒（另有终止回收宽限），输出须与目标版本完全一致且不超过 128 字节。

开发证书仅用于已授权的本机验证，不把“通过本机程序身份校验”解释为系统接受跨设备正式分发。面向其他用户发布前需另行验证分发方案与权限连续性。

# 首次身份迁移

迁移前运行程序是 ad-hoc 签名，不能提供稳定的升级信任来源。2026-10-07 已通过明确迁移入口完成本机固定 Apple Development 身份安装，随后多次普通同身份替换通过；当前运行程序不再是 ad-hoc。普通安装／更新仍拒绝隐式迁移。已实现明确的本机迁移入口 `automnt --migrate-signing --team TEAM_ID`，从已签名候选副本运行；指定 Team 必须与候选签名一致。仅接受标识 `automnt` 且完整性有效的 ad-hoc 旧程序，拒绝稳定身份再次迁移。替换前在同目录保留权限 0700 的随机名旧二进制备份，原子替换并验证新身份，失败回滚；配置、恢复历史和服务注册不由迁移入口改写。首次迁移可能触发系统授权；用户完成该首次授权后，才能进行两个版本间的正常升级连续性验收。不得自动点击、清理 TCC 或关闭保护。

# 本机签名操作

```bash
: "${AUTOMNT_SIGNING_IDENTITY:?必须提供参考项目所用的固定 Apple Development 证书身份}"
codesign --force --sign "$AUTOMNT_SIGNING_IDENTITY" --identifier automnt ./automnt
codesign --verify --strict --verbose=2 ./automnt
codesign --display --requirements - ./automnt
```

参考项目的证书指纹只用于本机选择和核验，不写入业务源码；签名凭据通过钥匙串安全提供。证书续期／轮换须重新核验要求兼容及实际授权继承。签名失败停止，不回退临时签名。
