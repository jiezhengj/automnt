**Feature**: 挂载丢失自动恢复（Mount Loss Auto-Recovery）

**Artifact**: Phase 0 技术调研与关键决策（Research & Key Decisions）

**Feature ID**: `004-mount-loss-recovery`

**Created**: 2026-10-05

**Input**: 规格（spec.md）、评估产物 `.specify/assessments/mount-recovery/`（含 72 小时实测取证）、宪法与黄金法则

# 1. 判别信号选型（三重信号）

- **Decision**: 判别“网络丢失 / 产品清理 / 使用者弹出”采用三重信号组合：
  1. **挂载表存在性 + 卷失效探测（新建）**：卷仍在但失效（会话重连中/死卷）= 网络丢失 → 清理并纳入恢复；现状代码只有字符串级“已挂载即健康”判定（`ensureMountPointReady`），**无失效探测**，须新建非阻塞判定（不得引入 `stat()` 阻塞路径，遵守源码既有“杜绝 stat() 阻塞”约束）；
  2. **两本自账（新建）**：挂载账（automnt 曾把哪些卷挂成健康态，**持久化为状态文件字段 `everHealthyMounted`**——卷已缺失时快照无法回溯历史，故必须落盘而非由当前快照推导）与清理账（automnt 清过哪些死卷，由清理动作写入）——现状**无清理账**，强制卸载函数仅有一个源不匹配调用点；卷缺失且非清理账所致 = 使用者弹出 → 会话抑制；automnt 永不提供弹出功能，排除法即归因；
  3. **卸载前丢失证据时间线**（**尽力而为**增强，非 MUST）：缺失前存在会话丢失证据 → 修复性弹出（弹掉死卷）→ 允许恢复；信号不可读时该增强自动失效、回退保守方向（与 FR-003 的条件式措辞一致）。
- **Rationale**: 评估阶段实测取证证明“网络丢失不产生卸载”（72 小时内 12+ 次会话重连、挂载全程在表）——**丢失侧已取证**；卸载侧（健康弹出的干净卸载）**样本未捕获**，其形状待需维护者批准时机的对照实验确认（见 §8 与评估 research 修正节）；DiskArbitration 官方头文件实锤事件无成因字段——“读意图”路线死亡，排除法+状态不对称是唯一不依赖意图读取的可行路线。三重信号的失败方向全部收敛为“少恢复 + 兜底入口”，不触碰误覆盖红线。
- **Alternatives considered**: ① DiskArbitration 事件判因——无成因字段，不可行；② 常驻观察进程逐事件归因——违宪（Constitution II）；③ 仅依赖系统日志文案——非公开 API，版本漂移单点风险，降级为增强而非基石；④ 时间窗启发式（弹出后 N 分钟内不重挂）——不可解释且与会话语义冲突，弃用。

# 2. 恢复状态持久载体

- **Decision**: 独立**附属状态文件**承载按卷粒度的会话抑制与待恢复标记（0600 权限、可丢弃重建、损坏即保守降级）。
- **Rationale**: 规格排除边界禁止除最小状态外的活动配置结构变更；会话抑制必须跨多次短命执行存活（事件驱动下无常驻内存）；可丢弃重建原则（FR-010）保证状态异常只会导致保守方向，永不导致意图覆盖。
- **Alternatives considered**: ① 活动配置新增键——属配置结构变更，触碰排除边界与“单一活动配置”审查面，拒绝（仅开关字段例外，见 §6）；② 纯内存状态——跨唤醒丢失，会话抑制失效，拒绝；③ 注册表/外部数据库——引入依赖，违反零依赖约束，拒绝。

# 3. 事件源扩展（触发模型）

- **Decision**: 复用既有 `RunAtLoad`（登录）+ `WatchPaths`（网络配置变化），**新增挂载命名空间事件**：系统级“文件系统挂载时启动作业”键 + 挂载目录增删监听，使使用者弹出、卷回归、会话恢复都能唤醒服务；全程零周期。
- **Rationale**: 评估调研实锤：官方提供“挂载时启动作业”事件键；现行 `WatchPaths` 被官方标注竞态、可能漏事件（本身是丢挂载后无人再管的第二根因候选）；`StartInterval` 官方语义在睡眠/运行中漏触发。事件模型同时满足 FR-009 与“杜绝轮询”对外承诺。
- **Alternatives considered**: ① 周期 `StartInterval`（方案 C）——被规格明确排除，仅作未来重新评估入口；② DiskArbitration 常驻观察回调——违宪（常驻等待进程）；③ 仅靠现有 `WatchPaths` 不扩展——弹出/回归无事件，覆盖不足，拒绝；④ 高频事件节流——事件本身稀疏，非必要。

# 4. 恢复执行链路

- **Decision**: 复用既有主机探活（TCP 445 非阻塞探测）、NetFS 静默挂载、`EvaluationRetryRunner` 有界重试（默认 ≤3 次、间隔 1s、总窗口 ≤10s）。**凭据来源澄清**：产品自身不含钥匙串代码，SMB 凭据由 NetFS 经系统钥匙串隐式提供；FR-006 的零对话框须由显式设置 NetFS 的 `kNAUIOptionNoUI` 保障（现 `silentMount` 传 `open_options = nil`，未设置）。
- **Rationale**: 与现有评估挂载同一链路，行为一致性与幂等天然成立；有界重试已是项目既定模式。
- **Alternatives considered**: ① 独立恢复执行器——重复实现两套挂载逻辑，拒绝；② 无限重试直到成功——违反 FR-005 有界要求，拒绝。

# 5. 死卷清理与自账联动

- **Decision**: 既有“断网失效挂载的超时强制清理”（含源性比对与强制卸载）执行成功时同步写入清理账（“待恢复”标记），主机可达的后续事件评估据此恢复。
- **Rationale**: 清理账把“产品弄没的卷”变成可归因事实，是三重信号第 2 条的自账半边；清理与恢复闭环天然复用。
- **Alternatives considered**: ① 不记账、清理后一律恢复——无法区分后续的使用者弹出，拒绝；② 复用日志文件解析当账——脆弱且引入解析维护面，拒绝。

# 6. 兜底通知与配置开关

- **Decision**: 兜底复用既有系统通知通道（**纯文本通知**，恢复判定轮去重：每轮至多一条，内容合并）+ `--config` 菜单“立即重新挂载”入口作为唯一一键路径；活动配置仅新增“自动恢复开关”字段，默认启用，随既有原地升舱迁移。
- **Rationale**: L4 是评估定稿的死角兜底；通知通道已有（更新通知先例）；开关满足 FR-008 且默认值贴合“傻瓜化”目标；配置字段经原地升舱零迁移风险。
- **Alternatives considered**: ① 无通知仅菜单——通知盲区（用户不打开菜单永远看不到），拒绝；② 每次失败都通知——轰炸，违反 US3 AC3，拒绝；③ 按卷/按主机粒度开关——v1 过度设计，需求未提出，拒绝（全局单开关）。

# 7. 会话边界定义

- **Decision**: 会话 = **新建**的网络上下文身份判定叠加登录会话，先到者解禁抑制。
- **Rationale**: 现有 `NetworkProfile` 为遗留结构且被迁移清空、`SystemConfiguration` 虽被 `import` 但未调用任何 API——**不存在可复用的网络身份机制**，必须新建（候选：系统网络状态/路由/接口身份快照）；语义可测、可解释，符合 FR-004 与维护者裁决。
- **Alternatives considered**: ① 空闲时间窗——拍脑袋且不可测，拒绝；② 仅登录会话——Tailscale 场景网络迁移频繁而登录不发生，抑制过久，拒绝。

# 8. 验收实验设计

- **Decision**: SC-001/SC-002 以**实机真实挂载**对照实验验收：断网-恢复、真实健康弹出、修复弹出三组；交互过程用伪终端记录；隔离环境仅作流程辅助；全程按项目证据纪律标注环境（实机/伪终端/隔离）。实验触碰真实挂载，时机需维护者批准。
- **Rationale**: 挂载/卸载是内核语义，只有真实挂载能验证；clarify Q2 已定口径；与 003 的证据先例一致。
- **Alternatives considered**: ① 仅伪终端+隔离配置——产生不了真实 SMB 卷，硬指标只能间接论证，拒绝为主证据；② 内存模拟自测——同理，仅覆盖判定逻辑层。

# 9. 信号降级路径

- **Decision**: 任何判别信号不可读/状态损坏 → 保守抑制 + 兜底入口；状态可丢弃重建（FR-010）。
- **Rationale**: 失败方向安全是评估给定的硬约束；降级路径使版本升级、日志漂移、状态丢失都不放大为意图覆盖。
- **Alternatives considered**: ① 失败时激进恢复——回到 3.0.0 故障模式，拒绝；② 失败时报错退出——破坏既有评估挂载主链路，拒绝。
