# 先立原则

这一版不从现有界面修补，而是从产品本身重新定义界面架构。产品只有一件事：**让配置好的 SMB 共享文件夹保持自动挂载**。因此自动挂载的开关是主角，打开/弹出是兜底，状态是证据。任何界面元素先回答"它属于哪一层、替谁承担什么"，再谈放在哪里。

三条不可违背的架构规则：

1. **一层只做一层的事。** 动作只出现在它所属的层级：全局动作在侧栏，服务器动作在服务器页，共享动作在共享行。任何一级都不借用另一级的界面。
2. **反馈回到动作发生的地方。** 侧栏排序的结果不出现在右侧，设置窗口的结果不出现在主窗口，共享开关的结果不出现在别处。直接操作成功默认静默，失败才说话。
3. **一个对象只有一个事实来源。** 自动挂载开关只出现一次；状态只出现一次；位置只在展开区出现一次。不做重复控件，不用第二个控件解释第一个控件。

# 层级与所有权

| 层级 | 对象 | 直接展示 | 直接可操作 | 收起 |
| --- | --- | --- | --- | --- |
| L0 全局 | App | 服务器列表、当前自动挂载是否生效 | 添加共享文件夹、打开设置、调整服务器顺序 | 总开关与全部应用设置（设置窗口） |
| L1 服务器 | 一台主机 | 名称/地址、这台服务器是否参与自动挂载、共享数量与异常数 | 服务器自动挂载开关、展开某个共享 | 服务器设置（名称、连接、索引） |
| L2 共享 | 一个卷宗 | 名称、状态、自动挂载开关 | 自动挂载开关、展开详情 | 挂载位置、手动打开/弹出、编辑、移除 |

全局动作只在 L0 出现，服务器设置只在 L1 出现，共享的编辑/移除只在 L2 展开区出现。没有跨层复制。

# 窗口结构

## 宽窗（≥ 700）

两列，不使用固定第三列：左列是 L0 全局区（服务器列表），右列是当前 L1 服务器页。共享不跳转页面，在右列内原位展开。这既遵守项目已有的"无固定第三列"，也遵守已经确认的"共享用展开收起"原则。

## 窄窗（< 700）

一条原生导航栈：根是 L0 服务器列表，进入某台服务器后是同一个 L1 服务器页。共享仍然原位展开，不增加第三层。返回键由系统提供。

没有共享二级页面，没有共享详情 sheet，也没有"点一下再点一下"的两层弹窗。

# 侧栏：全局层

## 结构（从上到下）

1. 侧栏头部：标题"服务器" + 两个全局动作。
2. 搜索服务器。
3. 已管理服务器（编号、名称、摘要、拖动手柄）。
4. 顺序说明一行。
5. 可添加服务器。
6. 没有底栏。没有底部图标，没有底部文字按钮。

## 全局动作的外观

头部右侧放两个 **28pt 的系统 Liquid Glass 符号按钮**：`plus`（添加共享文件夹）与 `gearshape`（设置）。使用 macOS 27 的 `.buttonStyle(.glass)`，不自定义背景、不加玻璃容器、不加描边。悬停有系统提示，辅助功能有完整标签。

为什么不是底部两个小图标：HIG 明确要求避免把关键动作放在侧栏底部（窗口移动后底部可能被挡住），而且底部孤立图标容易被读成状态栏装饰。
为什么不是文字按钮：全局区是导航与层级，不是内容；文字按钮会把导航读成表单。
为什么是玻璃符号：这是 macOS 27 原生按钮材质，和窗口其他玻璃元素一致，不需要自绘。

窄窗没有侧栏，所以同样的两个符号放在窗口工具栏最前（根层），顺序与位置和宽窗侧栏头部保持一致。

## 侧栏行的内容

编号徽标、名称、摘要（已管理 N · 可添加 N）、拖动手柄。行内不放任何动作。顺序调整成功时**不弹提示**，列表本身就是结果；失败时用侧栏动作自己的 alert 说明原因，不在右侧显示。

# 右侧：服务器页

## 直接展示

- 服务器身份：图标 + 地址（标题在工具栏，不在正文重复）。
- 这台服务器是否参与自动挂载：开关 + 一行后果说明。
- 共享列表：每个共享一行，行内直接展示状态与自动挂载开关。

## 直接可操作

- 服务器自动挂载开关。
- 每个共享的自动挂载开关。
- 展开某个共享（行尾 chevron）。

## 收起

- 共享的挂载位置。
- 手动打开、弹出。
- 编辑共享文件夹、从 Automnt 中移除。
- 服务器设置（名称、连接、索引）在独立 sheet 中。

## 服务器设置入口

不在正文放文字按钮。服务器被选中时，工具栏尾端出现 `slider.horizontal.3` 符号按钮（悬停"服务器设置"），打开原生 sheet。它是这一层的上下文动作，和右侧的搜索并列，不抢内容的注意力。

## 自动挂载的依赖链

总开关（设置窗口）→ 服务器开关 → 共享开关。界面必须如实表达这条链：

- 总开关关闭：服务器页顶部出现一条"自动挂载已关闭"的状态行和"打开设置"按钮；服务器与共享开关保持实际保存的意图但不可操作，避免"开关是开的却什么都不发生"。
- 服务器关闭：服务器开关为关；共享开关不可操作，服务器开关下方的一行说明解释"关闭后此服务器的共享不再自动挂载"。
- 两级都打开：共享开关可操作。

开关只改"意图"，行内状态显示"事实"；两者分开表达，不用一个冒充另一个。

## 共享行

```
[状态符号] 共享名称                         [自动挂载开关]  chevron
           状态文字（次要）
```

- 行内不放"在 Finder 中打开"。打开是兜底动作，不是这一层的核心。
- 状态文字只写事实：可用、未挂载、本会话已弹出、位置被占用、服务器不可达、需要登录、挂载失败、正在挂载、上轮未检查。
- 行点击与 chevron 都用于展开/收起；开关是独立命中区。
- 可添加的共享：名称 + "添加"按钮，不展开。

## 展开区

只放"行里放不下、又确实属于这个共享"的内容，顺序固定：

1. **挂载位置**：标签 + 路径（可选中）。实际位置与保存位置不一致时，只在这一行下面加一行说明和"使用此位置"。位置是属性，不是动作。
2. **手动操作**：在 Finder 中打开 / 连接并打开 / 查看占用位置（按状态只出现一个主手动动作），以及"弹出"。这些是兜底能力，用次要按钮，不与开关抢层级。
3. **管理**（分隔线之后）：编辑共享文件夹…、从 Automnt 中移除…。编辑/移除是对整个共享的操作，必须与位置、手动操作分开，移除用红色并在确认对话框中说明已挂载的卷宗不受影响。

不在展开区重复自动挂载开关，不在展开区重复状态，不在位置行放编辑/删除图标。展开区也不放第二个"打开"按钮。

顺序的理由：先回答"它在哪里"，再回答"现在能拿它做什么"，最后回答"如何修改或移除它"；破坏性动作永远最后，并且和属性分开。

## 异常

不设重复的"需要注意"列表。共享行本身已经显示状态；服务器页顶部只在服务器层面出问题（不可达、需要登录、后台未运行）时给一条状态，具体共享仍由各行表达。

# 反馈架构

反馈不是"有地方就塞"，而是按动作发生地分配：

| 动作发生地 | 成功 | 失败 |
| --- | --- | --- |
| 侧栏排序 | 静默，列表即时更新 | 侧栏动作自己的 alert，说明原因并可重试 |
| 侧栏添加 | 添加 sheet 内完成；新对象出现在列表/服务器页 | 添加 sheet 内字段旁或表单顶部 |
| 服务器页开关 | 静默，开关与状态行即时更新 | 服务器页顶部一条内联状态，不弹窗 |
| 共享行开关 | 静默 | 服务器页顶部或行内说明 |
| 共享展开区手动动作 | 静默：状态与行文字更新 | 展开区附近一条内联说明 |
| 服务器设置 sheet | 保存后关闭，不弹成功提示 | sheet 内保留输入并说明原因 |
| 设置窗口 | 窗口内状态行 | 窗口内说明 |
| 菜单栏 | 菜单栏内一行 | 菜单栏内一行 |

实现要求：

- 消息带 surface 标记（侧栏 / 主窗口 / 设置 / sheet / 菜单栏），视图只显示自己的 surface。
- 删除所有成功 toast：排序、添加、移除、挂载、弹出、开关保存都靠对象与状态变化表达，不弹成功文案；只保留"当前状态"说明（如设置窗口里的后台运行状态）和失败说明。
- 排序失败使用独立 alert，不写入主窗口的 issue。
- 设置窗口产生的消息只留在设置窗口；主窗口不再显示设置的消息。
- 主窗口每个页面最多一条常驻状态行，新消息替换旧消息，不叠多张卡片。

当前需要纠正的错位：排序成功提示出现在右侧；设置保存提示可能同时出现在主窗口；添加/移除/挂载/弹出的成功提示会跨页面出现；侧栏动作没有自己的失败出口；"立即检查"是全局动作，结果却只落在当前选中的服务器页（应改为各对象状态自行表达，菜单栏保留自己的一行）。全面检查以本表为准。

# 工具栏、菜单、键盘

- 宽窗工具栏：前缘只有系统侧栏开关；尾端是共享搜索与服务器设置符号。全局动作不在窗口工具栏（它们在侧栏头部）。
- 窄窗工具栏：前缘是返回（进入服务器后）、添加与设置（根层）；尾端是搜索与服务器设置。
- 菜单：Servers（立即检查 ⌘R、上移/下移）、App 菜单（设置 ⌘,）、Help。
- 键盘：⌥↑/⌥↓ 调整服务器顺序；Return/空格展开共享；Esc 收起展开；Tab 焦点顺序按行、开关、chevron、展开区动作。
- 辅助功能：开关标签包含对象名（"自动挂载 finalhome"）；行有展开/收起提示与状态；路径可选中；移除后焦点落到下一个共享，排序后焦点跟随被移动的服务器。

# 动效、声音、外观

- 展开/收起使用系统默认动画；减少动态效果时不做动画。
- 不新增应用音效；沿用已确认的"不采用"决定。
- 只用系统语义颜色、材质、控件尺寸；不自定义窗口装饰、不加玻璃容器。玻璃只出现在系统按钮样式本身。
- 浅色、深色、较大系统文字、窄窗、长译文都要在设计阶段留出换行和滚动，不靠缩字。

# 明确不做

- 固定第三列。
- 共享二级页面、共享详情 sheet、共享编辑的第二层 sheet。
- 侧栏底部动作条、底部两个小图标、任何形式的全局文字胶囊。
- 服务器正文里的"服务器设置"文字按钮。
- 每行一个"在 Finder 中打开"作为主操作。
- 重复的自动挂载开关、重复的状态、重复的异常列表。
- ⋯ 收纳菜单、临时按钮、刷新/检查按钮。
- 把跨界面的提示文案塞进侧栏或详情来"解决"位置问题。

# 从现有代码迁移的顺序

1. 先恢复已知可编译状态，删除本轮试错产物（共享二级页面、页面路由、底部动作栏、正文服务器设置按钮）。
2. 侧栏头部：标题 + 两个玻璃符号按钮；窄窗工具栏放同样的两个符号；删除窗口工具栏里的全局项。
3. 服务器页：身份行、总开关关闭时的状态行、服务器开关、共享行（状态 + 开关 + chevron）；删除重复的异常列表。
4. 共享展开区：位置 → 手动操作 → 管理；删除行内打开按钮，删除展开区里的自动挂载开关。
5. 服务器设置：工具栏符号入口；从 sheet 移除与页面重复的参与开关。
6. 反馈：给消息加 surface；删除排序成功 notice；排序失败改 alert；设置消息只留设置窗口；全面核对本文件的反馈表。
7. 验收：宽窗/窄窗真实窗口、浅/深色、九语最长文案、较大文字、VoiceOver、键盘；`swift test` 321 项；本地化门；Release 构建与签名；截图与证据文档。

# HIG 与平台依据

- Sidebars：避免把关键动作放在侧栏底部；侧栏层级不超过两层；用分组表达层级。https://developer.apple.com/design/human-interface-guidelines/sidebars
- Lists and tables：行内容保持简短；内容多时用行标题，进入详情视图看内容；披露指示器只用于进入下一层。https://developer.apple.com/design/human-interface-guidelines/lists-and-tables
- Split views：侧栏 + 次级 pane 表达层级；项目约束是不设固定第三列。https://developer.apple.com/design/human-interface-guidelines/split-views
- Toolbars：符号优先、尾端放搜索与上下文设置动作，一个窗口只保留一个主操作。https://developer.apple.com/design/human-interface-guidelines/toolbars
- Liquid Glass / Materials：使用系统材质与 `.buttonStyle(.glass)`，不自绘玻璃。https://developer.apple.com/design/human-interface-guidelines/materials
- 2026-10-21 通过文本代理读取上述页面；macOS 27 SDK 已确认 `GlassButtonStyle`（`.buttonStyle(.glass)`）存在。HIG 页面为动态渲染，未能逐字核对全部段落，已核对的部分以链接为准。
