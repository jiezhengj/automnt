# 用户场景与验收测试

## 用户故事 1 — 配置后让 SMB 文件任务自动可用（Priority: P1）

用户购买并首次设置后，配置的共享在服务可达、凭据有效时自动挂载。之后的登录、网络恢复和卷宗丢失由后台处理，不要求用户先遇到任务错误，再去点击挂载。

**优先理由**：自动挂载是产品成立的前提，不能以漂亮的手动挂载器代替。

**独立验收**：仅配置一个真实 SMB 共享，完成首次授权，关闭配置窗口；通过真实文件读写检查登录后就绪、网络中断恢复、丢挂载恢复，并记录人工操作和系统提示。业务配置必须通过产品自身创建。

**验收场景**：

1. **Given** 未配置用户有可达 SMB 共享，**When** 通过 GUI 选择探测结果或明确输入目标并完成必要首次授权，**Then** 配置被保存，共享自动挂载，真实文件任务能使用约定路径；无需安装外部 CLI 才获得核心能力。
2. **Given** 已配置且后台获准运行，**When** 用户关闭设置窗口并重新登录，**Then** 系统在登录触发的挂载评估中自动处理启用目标，窗口无需先打开，不逐次请求已授予的同类权限。
3. **Given** 卷因网络中断失效或丢失，**When** 主机恢复可达且系统收到恢复评估事件，**Then** 当轮有界评估自动恢复可恢复的卷，任务再次能读写；不得以 UI 状态代替文件可用证据。
4. **Given** 卷健康且用户在 Finder 手动弹出，**When** 本可达会话内再次评估，**Then** 不重新挂载；网络上下文变化或重新登录后解除抑制。失效卷的修复性弹出不得误判为弃用。
5. **Given** 凭据失效或服务器不可达，**When** 自动尝试失败，**Then** 明确说明原因类别、当前自动化状态与用户可采取的下一步；有界退出，不持续弹窗、循环尝试或冻结界面。
6. **Given** 自动化已开启，**When** 用户明确停用，**Then** 不再发起新的后台挂载；关闭窗口、退出配置界面与停用的区别在交互中明确表达。
7. **Given** 自动化已获准且菜单栏功能未开启，**When** 用户关闭窗口或按 ⌘Q 退出，**Then** 无须保留 GUI 或菜单栏图标，后台仍按系统事件执行自动挂载。
8. **Given** 用户开启可选菜单栏功能且共享健康，**When** 点击快捷卸载，**Then** 当前会话内不自动重挂；网络上下文变化或重新登录后恢复资格，点快捷挂载则立即解除该目标抑制并发起有界尝试。卸载失败应说明原因，不将失败显示为已卸载，不强制中断正在使用的文件任务。

## 用户故事 2 — 免费 CLI 与 GUI 使用同一产品能力（Priority: P1）

用户可以继续只使用免费 CLI，也可以使用 GUI；两者对相同配置意图采用相同挂载、恢复和健康弹出语义，安装两者不会引入竞争服务或长期配置分裂。

**优先理由**：共同演进是明确产品契约，也保护现有用户。

**独立验收**：使用程序生成的真实配置，分别运行两种入口并在同时安装条件下修改同一共享；对照挂载结果、恢复规则和配置状态，检查不丢失原有配置。

**验收场景**：

1. **Given** 仅使用现有 CLI，**When** 引入 GUI Feature 后运行和升级 CLI，**Then** 免费自动挂载能力、预编译获取方式及已确认恢复语义继续可用，不因 GUI 收费被削减。
2. **Given** 用户已有有效 CLI 配置，**When** 打开 GUI，**Then** 自动呈现同一配置，程序确定内部位置，必要许可只决定允许或拒绝，无内部目录选择、导入或检查；必要系统许可单独说明，不丢目标或用户意图，不产生第二活动配置和后台服务。
3. **Given** 两种入口均已安装，**When** 修改启用目标或同时触发评估，**Then** 只产生一致结果，无重复挂载、相互覆盖或第二套常驻评估进程。
4. **Given** 某项共同挂载规则或恢复缺陷获得修复，**When** 构建两个发行入口，**Then** 两者共享该修复；允许渠道安装、授权和更新方式不同，不允许复制成长期业务分叉。

## 用户故事 3 — 低价但精美、清楚、符合 Mac 习惯（Priority: P1）

用户能在精简、优雅的原生界面完成首次设置、管理目标和理解异常。正常时界面安静；异常时能知道哪里出了问题，不需要阅读内部实现或命令输出。

**优先理由**：视觉与交互品质属于正式产品要求，不是可发布之后的可选美化。

**独立验收**：走查首次设置、无目标、探测中、健康、服务器离线、授权被拒、挂载失败和编辑保存等状态；取得运行中的真实截图与操作记录，检查浅色/深色、不同窗口宽度、键盘与 VoiceOver。

**验收场景**：

1. **Given** 首次运行且无配置，**When** 用户进入设置，**Then** 清楚说明自动挂载目的、必要授权与下一步，空状态有直接行动，不出现空白页面或默认个人目标。
2. **Given** 目标列表中存在健康、离线和失败项，**When** 查看状态，**Then** 层级、文字与图形清楚区分，状态不只靠颜色；手动重试是异常兜底，正常页面不暗示每次必须点连接。
3. **Given** 探测或挂载耗时，**When** 用户继续编辑或取消交互，**Then** 界面保持响应，忙碌、可取消和不可重复提交状态明确；失败可恢复且不丢失尚未保存的输入。
4. **Given** 用户用键盘或 VoiceOver，**When** 完成配置、修改目标或处理异常，**Then** 主要操作均可到达，焦点顺序和朗读名称可理解，无仅鼠标可用的关键控件。
5. **Given** 浅色/深色、增加对比度、减少动态效果或调整窗口大小，**When** 浏览所有关键状态，**Then** 内容完整可读，布局、材料、图标与动画协调，不出现遮挡、截断关键动作或不必要的炫技动画。
6. **Given** 设置尚未保存或操作具有破坏性，**When** 关闭、取消或执行该操作，**Then** 遵循一致的保存/取消与确认语义，避免无提示丢失编辑；配置主流程不突出手动挂载；用户主动开启的菜单栏快捷菜单允许快捷挂载与卸载，默认关闭。

## 边界情景

- 网络无响应、探测零结果、多服务器同名共享、目标重命名或路径冲突：提示可理解原因，不静默切换到任务未配置的路径。
- 凭据取消/失效、首次授权被拒、授权被撤销：不绕过系统保护，明确恢复步骤；重复正常升级不应变成每次授权。
- 健康弹出与失效卷清理：菜单栏主动卸载健康共享与 Finder 健康弹出采用同一会话抑制规则，网络上下文变化或重新登录后解除；快捷挂载可立即解除该目标的抑制。失效卷修复仍与弃用意图区分，不因清理而禁用恢复。
- 网络恢复无事件到达：如实保持现有事件边界，不承诺任意访问即时连接；不能以隐藏轮询或新增常驻服务假装满足旧语义。
- GUI 与 CLI 同时修改、后台正评估时改配置、迁移中断：保留单一活动意图、避免丢数据，处理并说明冲突。
- 未保存输入、窗口关闭、应用退出、后台停用：交互和运行语义分别明确；停用不冒充卸载已有卷。
- 状态刷新、批量目标、大文字、窄窗口、深色、辅助功能与长错误信息：关键信息和操作可见，主界面不被日志淹没。
- 发布截图隐私：不得暴露真实个人网络地址、用户名或文件内容；演示数据必须由显式独立展示模式提供或对真实截图脱敏，不伪写运行配置。
- 免费签名不能完成某项渠道验证、其他 OS 未可用、无外部用户样本：如实标注，不设计需要不存在设备、凭据或服务才能通过的前置 Task。
- 必要能力在沙盒内无法实现：属于实际产品阻塞，不能归为“只差开发者账号”，也不能降级成手动工具后宣布完成。

## 维护者指定的技术与平台约束

本节是直接产品指令，保留到 plan；不是本阶段的模块/API 设计。

## 关键对象

- **共享目标**：用户选择/输入的服务器与 SMB 共享、启用意图、任务使用路径；不包含明文凭据。

# 假设、范围与依赖

## 明确范围

首版只围绕 SMB 自动挂载与恢复、必要配置/诊断、精美原生 GUI、CLI 共存和完整商店准备。不能以低价减配品质，也不把“只差账号”缩减成只完成可编译原型。

GUI 是按需打开的配置入口，关闭窗口或按 ⌘Q 退出界面均不停止已获准的自动挂载；通过独立明确的停用入口停止后台自动化。菜单栏图标与快捷菜单是用户单独开启的可选功能，默认关闭，允许快捷挂载和卸载；不要求配置 GUI 常驻才能完成核心自动化。菜单栏开启时 UI 生命周期及系统服务适配由 plan 决定，不增加独立常驻评估循环。

不新增协议、云账号或订阅；不承诺修复 Finder 侧边栏、不承诺 Windows 式按任意路径访问即时连接。已有 CLI 的事件驱动恢复仍有延迟和无事件角落；若实际商店能力要求行为改变，必须在后续阶段明确审阅，而非隐藏更改。

## 现实环境与证据边界

2026-10-07 只读确认本机 **Xcode 27.0（27A266a）** 与 **macOS SDK 27.0**，支持当前指定开发范围。未在本阶段验证 GUI 沙盒挂载、Keychain、后台注册、图形运行、最终签名或审核；本机工具存在不等同功能通过。

真实网络目标必须来自用户明确输入或已有真实探测，并经产品自身生成配置；不得编造连接或未经授权干扰用户文件任务。验收环境的准备由可执行的产品功能与可控测试支持完成。若需要用户进行本机授权或短暂网络操作，应说明影响和具体操作，不能假设代理有能力自动处理系统安全弹窗。

隐私/支持内容、法律联系人和商店身份资料是发行准备的一部分：plan 必须盘点当前项目真实可用资源，优先复用可达的项目托管渠道，不擅自购买域名或发布个人信息。需要维护者输入的信息在账号无关阶段收集，不留作最后额外阻塞。维护者已在 clarify 确认首版无遥测、广告或第三方分析，不自动上传诊断；本机诊断与脱敏导出由用户主动操作。最终隐私声明必须与实际实现核对，不得以政策文案代替行为验证。

## 后续 Task 编排约束

Tasks 已生成并经历本地实施，历史完成状态保留；本轮只修订意图和追加未完成的 T083–T094，不执行新代码修复。后续实施遵守以下依赖顺序：

1. 先清点并验证当前环境能执行的核心自动化/沙盒边界，缺口必须是具体能力工作，不做无终点调研或等待未购账号。
2. 共用产品能力、GUI 完整流程和早期视觉设计可按真实依赖并行；不能将视觉/交互集中为实施完成之后的可选尾项。完整质量走查与修复必须在发布准备前结束。
3. 完成真实挂载/恢复、CLI 共存、免费身份范围内升级权限验收及本地构建；在此期间完成图标、截图、文案、支持与隐私材料、审核说明和最低 OS 审计。
4. 对账号无关成果收敛并修复遗漏，直到没有可继续完成却被留给账号之后的产品任务。
5. 付费账号启用放到最后的外部依赖边界。仅真正需要账号的证书/profile、App Store Connect 项目和价格/申报配置、目标身份渠道验收、上传、提交及审核反馈处理依赖它；无账号时标为待执行，不堵塞前面的独立工作。
6. 每个 Task 必须说明可执行输入、产出与通过条件。不得把招募一定数量用户、购买额外设备/域名、取得 Apple 预批准、搭建未知公共服务器或自动通过审核设计成代理必然可完成的前置 Task。可自动检查、实机走查与确需维护者操作的步骤分别表达，不用空泛“保证精美/保证合规”冒充工作。

“仅付费账号阻塞”指账号是最后唯一尚未具备的外部前置条件；签名、上传和 Apple 审核均是账号依赖的后续动作，不能提前完成，也不能承诺第三方审核结果。若还存在沙盒能力、稳定授权、视觉质量或真实运行未解决项，就不能宣布达到这个状态。

## 商店宣传政策依据

2026-10-07 实际读取 [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)：2.3 要求元数据准确、以本产品体验为中心；2.3.7 对名称、副标题、截图等字段的价格/不适当宣传有限制；3.1.1(a) 的区域限制针对指向其他购买机制；2.4.5、2.5.2 限制下载/安装代码来改变应用功能；5.1.1 要求元数据和应用内有可达隐私政策。

条文未发现明文禁止介绍免费开源源码或独立免费 CLI，免费获取也不是外部收费购买；这是对当前条文的判断，**不是 Apple 针对具体推荐文案的批准**。准备事实准确的候选文案和不影响产品完整性的替代措辞，提交时复核政策并应对审核反馈。链接免费 CLI 不得变成安装它以解锁商店功能。对外使用“开源、低价买断、完整功能”优先于不可验证的绝对“无溢价”声明，同时保留维护者的透明低价定位。

本阶段沿用用户此前对 developer.apple.com 公开只读获取的授权及公网 peer 验证例外：HTTPS 校验证书、无登录、不自动跟随重定向；网页内容仅作条文证据。

# 全产品交互补充要求

本节与 FR-024–026 一起定义当前文档/demo；旧排序草稿及例行弹出确认已被替代，历史记录保留。

- **FR-027**：侧栏分为已管理服务器和未管理的发现服务器；已管理服务器直接拖放排序，即时原子保存，可撤销且支持键盘等价操作。并发修改或撤销冲突显示原因且不覆盖最新顺序。首个共享添加使服务器追加到已管理末尾，刷新不自行排序或改变选择。服务器优先级仍按首可达策略排他选择，不扩展为并行多 NAS 自动挂载。
- **FR-028**：界面选择、本轮评估所选服务器和已有挂载独立表示。全局自动挂载显示实际后台状态、观测时间及恢复下一步；添加配置成功、后台启用成功和共享实际可用各有独立结果。读取失败有错误状态，不变成首次空态。
- **FR-029**：完整评估、单共享挂载/重试和刷新明确区分范围；对象进度不抢焦点，重复请求协调，失败按范围合并。简单开关立即保存，名称行内确认；相关服务器地址和挂载路径变更共同校验、提交，失败保留输入。
- **FR-030**：详情顺序为状态、约定与实际位置、自动安排、编辑/移除/弹出、索引诊断。普通弹出直接执行且繁忙失败不强制；移除管理配置不弹出、不删除远端文件，最后共享移除同步删除服务器，保留并发保护与稳定选择回退。
- **FR-031**：设置完整覆盖实际自动挂载/恢复、菜单与登录、实际系统通知授权及独立声音、共享重试参数、支持；跟随系统语言与外观，原生关于/帮助、离线支持/许可和脱敏导出预览均可达。通知点击读取最新状态，多问题用当前失败摘要；退出保持后台、升级保留配置和偏好、owner 接管须明确同意。
- **FR-032**：配置规则、完整评估、单共享和普通弹出均由共同核心提供结构化结果，各入口只适配交互/权限/渠道。CLI 已提供 `automnt --mount <smb-url>` 与 `automnt --eject <smb-url>`（T077 已实现并含回归测试）：仅作用于活动配置中的唯一目标，绝不跨服务器模糊匹配；参数/目标错误非 0 退出；弹出为普通非强制、繁忙如实失败。GUI 与 CLI 共用同一规则与失败分类词汇，不以执行外部 CLI 实现自身能力。内核调用实现按各自构建方式分置（CLI 扁平单二进制不依赖 `AutomntPlatform`），修改其一必须同步核对另一处。真实 CLI 挂载与普通内核弹出已有部分实证（T078）；GUI/helper 的相应能力和方案 A 授权仍未实测。

验收追溯：FR-027–032 对应 T071–T078，需求质量评审 CHK050–CHK061；按 quickstart 的全产品场景复验。系统认证、CLI 透明配置、owner 协调和原生运行仍未验证。

# 方案 A 的配置授权要求

- **FR-033**：CLI 与 GUI（含 GUI-only）使用真实账户固定 `~/Library/Application Support/automnt/automnt.plist`。程序确定、依法准备此目录；正常首次、设置、共用与恢复不展示内部路径、不要求寻找或选择目录，不提供位置/更改/导入字段。需要许可时用户只决定允许或拒绝，实际系统机制、各身份权限与升级连续性必须证明；普通应用 Alert 不授予沙盒文件权限。有效访问自动读取已有目标，首次有效添加才创建业务配置；取消或失败不创建配置副本、不新挂载或接管。
- **FR-034**：未授权、取消、目录缺失、访问记录陈旧、权限撤销和配置读/解析失败分别显示原因及下一步；历史 wrongDirectory 保留内部诊断兼容，不作为新正常用户步骤。这些状态不得显示“已管理 0”、真实空态或触发新配置。成功访问并读取确认无目标才可显示空态。失败保留只读快照；恢复后重读最新 revision，保留目标、顺序、未知字段、开关与恢复意图。主窗、详情、编辑、设置、菜单和快捷键统一配置可写及后台动作就绪门禁。
- **FR-035**：配置目录访问、后台服务许可、SMB 系统认证和外部挂载位置权限分别处理。退出 GUI 后的独立后台必须具有经证明的固定配置目录访问能力；不足时有界退出、保留 needsAuthorization、前台修复，不后台弹窗或依赖 GUI 常开。首次读配置不自动接管后台，单活动配置、稳定锁和单 owner 不变。

## 新增可验证结果

- **SC-012**：已有 CLI 配置用户无需寻找或选择内部目录，无导入/检查即可自动看到全部合法目标；需许可时只决定允许或拒绝，再次启动复用合法访问。CLI/GUI 交替保存重读一致；过期草稿和目标消失明确冲突。首次/取消/目录缺失/撤销/损坏均无零目标误报、新副本、新挂载或自动接管。
- **SC-013**：在真实稳定签名沙盒身份下，GUI 退出、真实重新登录、真实重启和正常升级后，后台仍读同一固定配置并在既有核心前提下完成真实 SMB 文件访问。权限撤销时无后台索权、无第二 owner；前台修复后读取最新意图。GUI/helper 各身份、桌面提示和真实文件访问均须记录，当前未执行方案 A 验收。

## 授权验收场景

1. 已有程序生成的 CLI 目标：程序确定固定目录，必要许可仅允许/拒绝，不寻找/选择内部目录；完整自动显示，再次启动合法复用访问。
2. 取消或拒绝：保持待授权且下一步可达，恢复按钮焦点；无路径寻找或目录选择指导、零目标统计、业务写入、新挂载或 owner 接管。
3. GUI-only 目录不存在：验证已裁定的合法访问机制和程序准备 0700 固定目录，无父目录/子目录选择或手工 New Folder；首次有效添加才创建业务配置，取消/失败不创建副本。不得用旧临时父 scope 实现冒充新要求通过。
4. 访问记录陈旧/撤销、配置损坏：分别给出重新授权或重读/修复入口，不覆盖原文件；修复后重读最新 revision。
5. GUI 退出后独立 helper、真实登录/重启/升级：验证自身访问、同配置/锁/owner 与真实自动挂载，不用 GUI 存活或容器探针替代。
