# 产品定位

automnt 是专为 macOS 设计的原生轻量级 SMB 自动挂载工具，基于目标主机 TCP 445 端口可达性自动匹配网络策略并挂载共享卷宗。程序通过 macOS 原生 NetFS 框架执行挂载；已有系统钥匙串凭据时无需交互输入密码，挂载失败返回明确状态并记录诊断日志。

# 立项背景与核心问题

本项目源于维护者在 macOS 日常使用 SMB 时遇到的持续性问题。以下系统体验是维护者报告的立项背景；Finder 行为从哪个 macOS 版本开始变化尚未核实。

- 在较早的 macOS 中，维护者可以把服务器主机本身添加到 Finder 侧边栏，方便访问主机下的共享；最近几个大版本中已无法按原来的方式添加主机。
- 即使把某个 SMB 共享卷宗添加到 Finder 侧边栏，重启等情况后也可能因卷宗没有自动挂载而丢失侧边栏入口。**automnt 当前尚不能解决 Finder 侧边栏入口消失的问题。**
- 更直接影响工作的情况是：需要读写 SMB 文件的任务先报错，用户才发现卷宗尚未挂载，不得不中断任务、打开 Finder 手动连接，然后重新执行任务。

维护者对 Windows 的体验是：在服务器可达、凭据和权限有效的前提下，任务可以通过网络路径访问文件，无需先手动挂载。这是对使用体验的比较，不表示 automnt 已实现 Windows 式按路径访问时即时连接的机制。

**automnt 的核心价值是自动挂载：在服务器可达、配置及凭据有效时，通过后台自动挂载和恢复，使配置的 SMB 卷宗尽可能在任务访问前就绪，减少“任务报错后才发现未挂载”的中断。** 当前事件驱动机制仍可能延迟恢复，不能保证任意时刻的访问都成功；服务器不可达、凭据失效等情况也不在可保证范围内。

CLI 与图形界面共用同一配置与自动挂载规则；CLI 仍然是免费、可脚本化的入口，图形界面负责查看状态、图形配置和异常兜底。手动挂载/重试仍不能替代自动挂载；若一个方案主要要求用户自己点击挂载，Finder 已提供该操作，它不满足本项目的核心目标。

# 核心特性

- **静默后台挂载**：基于 macOS 原生 NetFS 系统框架调用，全后台静默执行，挂载过程不弹出任何 Finder 窗口，不干扰日常桌面操作。
- **目标服务可达性路由**：全面基于主机 TCP 445 端口探测（`HostReachabilityProbe`）判定网络环境，无需依赖不稳定的链路层 MAC 地址或 ARP 缓存。
- **单用户标准安装与 CLI 自动注入**：规范安装于 `~/Library/Application Support/automnt/bin/automnt`，自动向当前用户的 Shell 配置文件（如 `.zshrc`、`.bash_profile`）注入 CLI 路径，打开终端即可全局使用 `automnt` 命令。
- **事件驱动响应式守护**：LaunchAgent 由 macOS 系统网络配置变更事件（`WatchPaths`）触发，严格杜绝定时器（`StartInterval`）轮询，空闲时零 CPU 与能耗占用。单轮网络评估引入有限重试机制（`EvaluationRetryRunner`），从容应对网络握手延迟。
- **断网失效挂载的有界清理**：采用 Darwin 内核 `MNT_NOWAIT` 非阻塞挂载表快照查询，杜绝 `stat()` 阻塞与系统彩虹球假死；仅对目标 SMB 挂载执行有时限的 `diskutil` 与 `umount -f` 强制清理。
- **单一活动配置契约**：系统统一使用 `~/Library/Application Support/automnt/automnt.plist` 作为唯一的运行时配置，严格采用 `0600` 权限安全原子写入。
- **Spotlight 索引防护**：挂载成功后自动请求 `mdutil -i off` 并尝试创建 `.metadata_never_index` 防护文件，避免网络卷宗被 Spotlight 建立索引导致性能下降。
- **免编译预编译升级**：通过官方 GitHub Release 直接下载对应版本的预编译二进制程序，在沙箱中完成签名与版本自验后原子替换，用户系统无需安装 Xcode 或 Swift 编译工具链。
- **安装完整性自检与自愈**：主程序启动时自动检测可执行文件、Shell 入口与守护服务状态，发现配置缺失或异常时自动触发原地自愈。
- **纯原生零依赖**：采用纯原生 Swift 编写，构建为针对 Apple silicon 原生优化的独立二进制可执行文件，无第三方运行时依赖。
- **交互式终端选单（3.2.0）**：初始化与日常配置使用方向键移动、Enter 选择的菜单，支持 Space 多选、长列表滚动和 Esc 安全取消；日常配置修改暂存至内存，只有选择“保存并退出”后才写入配置。

- **挂载丢失自动恢复（3.3.0）**：远程主机恢复可达后，配置启用且此前已挂载的共享卷会在下一次事件唤醒的当轮评估中自动重新挂载，全程无需人工操作、不弹出任何凭据或登录对话框；自动恢复只会重挂“此前确实挂载过”的卷，从未挂载过的新增卷按原有挂载评估逻辑处理（不会因恢复逻辑而漏挂或误挂）。
- **会话级抑制（尊重手动弹出）**：使用者在卷健康时手动弹出的共享卷，在本可达会话内不会被自动重新挂载；当网络上下文发生变化或重新登录（先到者为准）后，抑制解除，该卷重新纳入自动恢复。若弹出的是已失效的死卷（修复动作而非弃用意图），该卷仍可在主机可达后自动恢复。
- **恢复失败兜底**：健康弹出及会话抑制不发失败通知。实际恢复失败时，系统发出一条纯文本通知列出未恢复的共享并指引到“立即重新挂载”入口；每轮评估至多一条通知，内容合并；同一卷同一会话至多两条，边界变化或挂载成功后计数归零。使用者也可在 `automnt --config` 主菜单中直接选择“立即重新挂载”手动触发一轮挂载评估。
- **自动恢复开关**：可在 `automnt --config` 主菜单的“自动恢复开关”项中切换；默认启用。关闭后行为回落至现状（仅登录与网络配置变化时评估），且“立即重新挂载”手动入口仍然可用。开关仅在“保存并退出”后落盘生效，按 `Esc` 退出则不变。

**边界说明**：CLI 提供 `--mount`/`--eject`，图形界面在共享详情中提供普通弹出；两者都不把强制卸载作为例行操作，繁忙卷会如实失败。程序仍可在恢复前清理检测到的死卷；健康“弹出”包括使用者在系统（如 Finder）或产品入口中发起的动作。


# 图形界面（本地构建，未随 GitHub Release 发布）

- 图形界面与 CLI 共用 `~/Library/Application Support/automnt/automnt.plist` 与同一挂载/恢复规则；GUI 退出后后台是否继续由真实后台状态决定。
- 首次启动由程序准备固定配置目录，不要求用户选择内部文件夹；已有 CLI 配置会自动显示。

- 本机 GUI 构建使用免费 Apple Development 签名，仅用于开发与本机验证，不是公众分发渠道，也未提交 App Store。

# 快速上手

## 系统要求

- 架构：Apple silicon（arm64）
- 操作系统：macOS 27.0 或更高版本

## 安装与首次运行

从 GitHub Release 下载预编译二进制 `automnt` 并运行：

```bash
chmod +x automnt
./automnt
```

程序首次在临时或下载目录运行时，将自动执行自搬迁与环境初始化：
1. 规范安装至 `~/Library/Application Support/automnt/bin/automnt`；
2. 清理原下载临时文件；
3. 向当前用户的 Shell 配置注入路径；
4. 提示在新终端窗口中直接运行 `automnt`。

## 从旧版本 (2.7.4) 升级

3.0.0 采用全新的单活动配置与事件驱动架构，不提供从 2.7.4 旧形态的原地升级路径。既有旧版本使用者请按以下步骤迁移：

1. 在旧环境中使用 2.7.4 原程序提供的卸载命令执行完整清理：
   ```bash
   ./<旧版程序> --uninstall
   ```
2. 下载 3.0.0 预编译程序并运行首次安装：
   ```bash
   chmod +x automnt
   ./automnt
   ```
3. 运行初始化向导重新生成规范配置：
   ```bash
   automnt --init
   ```

> [!NOTE]
> 3.0.0 遵循纯粹单一模型架构，旧配置不会被沿用，请在向导中重新勾选或录入当前挂载目标。

## 初始化配置 (`automnt --init`)

首次使用前，请确保已在 Finder 中通过“连接服务器 (`Cmd + K`)”成功连接过目标 NAS 共享卷宗，并在提示时勾选了“在钥匙串中记住此密码”。

运行交互式初始化向导：

```bash
automnt --init
```

向导通过终端菜单配置主机与更新策略：

- 候选主机与“手动添加”“跳过”“完成”等操作显示在同一单选列表中。使用方向键或 `j`/`k` 移动，按 `Enter` 选择；已配置主机不可重复选择。
- 选择候选主机后，可编辑友好名称并从该主机当前挂载的 SMB 共享中多选。按 `Space` 切换勾选，按 `a` 全选或清空，按 `Enter` 提交；名称留空时使用主机地址。
- 在向导菜单或文本输入中按 `Esc` 可取消当前步骤并返回；尚未完成的向导不会保存配置。
- 选择更新策略后，向导会询问是否部署 LaunchAgent。完成向导后保存配置；通过管道等非交互输入运行时，选择菜单会退化为编号列表；输入有效编号可选择，直接回车则取消。

> [!IMPORTANT]
> **注意：`--init` 默认保护现有配置**
> - 若已有可用配置，`automnt --init` 会自动保留现有配置。
> - 若需清空并从头重建配置，请明确执行 `automnt --init --reset`。写入前系统会自动生成带时间戳的 `.bak` 备份。

## 日常配置管理 (`automnt --config`)

日常如需新增共享挂载点、调整探测主机或修改更新信道，运行配置管理菜单：

```bash
automnt --config
```

主菜单将配置的主机与管理操作整合为单选列表。方向键移动光标，按 `Enter` 打开主机的共享管理或选择操作；共享通过 `Space` 多选后按 `Enter` 批量提交。调整主机顺位分两步完成：先选主机，再选目标顺位。删除主机或清空配置前，须将确认选项移动到目标项并按 `Space` 明确勾选，再按 `Enter`；直接回车会安全取消。

所有修改先保存在本次会话的内存工作副本中。选择“保存并退出”后才会写入配置；按 `Esc` 退出会放弃本次会话的未保存修改。

# 技术原理

## 主机服务端口探测 (HostReachabilityProbe)

系统采用非阻塞式 TCP Socket 连接探测指定目标主机（如 NAS 或服务器）的 445 端口：
- 对局域网或远程节点发送连接请求并设定有界超时（默认 1000 毫秒）；
- 端口可连接即判定该策略处于可达网络环境中；
- 连接被拒绝、主机不可达或超时即判定该网络策略未命中，继续向下评估下一策略。

## 事件驱动守护与自愈

- **网络事件监听**：LaunchAgent 配置文件注册 `WatchPaths` 监听 `/Library/Preferences/SystemConfiguration`，当网络发生切换（如从 Wi-Fi 切换到有线、连接/断开 VPN 等）时由 launchd 唤起执行。
- **重试调度**：唤起后通过 `EvaluationRetryRunner` 在指定时间窗口内进行有限重试，当网络握手建立后立即执行挂载；若重试窗口结束仍无任何策略命中，以退出码 `2` 静默退出，杜绝无限空转。
- **自动自愈**：主程序启动时读取 `InstallState`，若发现 LaunchAgent 缺失、配置失效或 Shell 入口被清理，自动进行无感自愈修复。

## 内核挂载表非阻塞扫描

为杜绝网络中断时标准文件系统调用 `stat()` 或 `FileManager` 造成的进程阻塞假死，automnt 采用 Darwin 原生内核接口：

```swift
let count = getfsstat(nil, 0, MNT_NOWAIT)
```

使用 `MNT_NOWAIT` 标志位直接从内核缓存中读取挂载快照，无论底层网络是否断开，调用均在微秒级立即返回。

## 卸载与清理

- 常规卸载：
  ```bash
  automnt --uninstall
  ```
  停止并注销 LaunchAgent 守护服务，从当前 Shell 配置文件中移除注入的 PATH 片段。用户的 `automnt.plist` 配置文件及日志目录被完整保留。

- 全量清理：
  ```bash
  automnt --uninstall --purge
  ```
  在常规卸载的基础上，彻底删除 `~/Library/Application Support/automnt` 及 `~/Library/Logs/automnt` 目录。
